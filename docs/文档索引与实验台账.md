- **2026-11-08 用户决定**：源域最终检测模型 = **GBT**（`gbt_full_train.pkl`）；后续跨域研究的深度特征骨干 = **T1 MSTCA**（固定 100 轮配方；全量训练权重未保留，需跨域阶段重训）；工作点 = 严格逐类召回不低于 T0 基线，后段 hover mode4 GPS 不作硬约束。部署阈值 0.3744，train-CV 误报比值 0.744 [0.620, 1.018]（A1 未通过、A2 通过）。事件级工作点：GBT onset 0.95（其余策略为部署默认），EV1–EV3 全部 PASS（见 3.4.1 节）。**内部 test 最终评价（用户批准，11-08）：CONFIRMED**；内部 test 已永久关闭，源域主线收尾，下一步转跨域。

### 0.3 当前最重要的三个结论

0. **源域模型已确定（用户 11-08 决定）**：GBT 为源域最终检测模型，T1 MSTCA 为跨域深度骨干；工作点为严格逐类召回≥T0（排除后段 hover mode4 GPS 硬约束），部署阈值 0.3744，误报比值 0.744 [0.620, 1.018]。
1. **源域候选已收敛到 GBT / E1**：Q1 在冻结的逐类召回≥T0 工作点下统一评价 14 个候选，GBT 类（0.59–0.68）全面优于纯 MSTCA（T1 0.822；W、S 均 >1）。冻结规则 KEEP=GBT；E1 点估计最好且在纳入后段 hover GPS 约束时显著优于 GBT（0.919 [0.856, 0.951]，描述性）。最终选择待用户决定。
2. **后段 hover GPS 不是模型能力问题**：Q2 显示 51% 的后段 GPS 窗口（mode4 z≠1）故障只存在于原始 GPS 高度，26 通道不可见；38%（mode4 z=1/恒等）在 hover 中无可测效应或无故障；仅 mode3（15%）可观测且 GBT 已检出。后段 hover 正常/故障还与飞行批次/悬停高度（故障约 15 m，独立正常中位 32–34 m）混杂。建议不再以后段 hover mode4 GPS 召回作硬约束，需用户批准后冻结。
3. **Real 泛化仍未解决**：源域窗口级成绩、源域事件级成绩和 Real 结果必须分开报告。现有 Real 测试集不能继续用于调参或选择模型。

### 1.2 状态定义：执行状态与实验判定分开记录

| 状态 | 含义 |
|---|---|
| 已完成 | 实验/分析已执行，已有结果报告；不代表通过 |
| 已完成·通过 | 已执行，且按事前冻结判据通过 |
| 已完成·未通过 | 已执行，但按冻结判据失败或属于 trade-off |
| 已完成·描述性 | 已完成分析，但不是预注册判定或独立确认 |
| 零训练分析 | 只复用已有预测/产物，没有训练模型 |
| 运行中 | 正式执行已启动，结果尚未完整归档 |
| 协议已冻结·待运行 | 方案、数据边界和判据已冻结，尚无正式运行结果 |
| 暂缓/待决策 | 需要先决定研究问题、评价标准或数据方案 |
| 历史/被替代 | 文档保留追溯；其数据、代码或协议已被后续版本取代 |
| 已锁定 | 该测试/数据已使用，不再用于新一轮调参或选择 |

**“已完成”不等于“成功”；“通过”也不等于“可以部署”。** 每条实验必须同时标明执行状态、冻结判定和证据范围。

## 6. 文档类型与事实来源优先级

| 文件类型 | 主要用途 | 能证明什么 |
|---|---|---|
| `configs/experiments/*.json` | 冻结实验参数、样本边界、判据和禁止事项 | 实验原本计划如何执行；不证明实验已运行 |

| `artifacts/*/evaluation.json`、`summary.json` | 机器可读指标、判定和汇总 | 与报告配套的结构化结果 |
| `scripts/research/*.py` | 训练、评估、审计和复算代码 | 实际实现；不能单凭脚本存在证明运行完成 |
| `tests/test_*.py`、`*_smoke*`、`*_preflight*` | 单元测试、环境门禁、流程检查 | 代码/流程门禁；不是模型性能 |

### 6.1 数据与测试边界

- 旧 10-30 正常来源采样结果来自后来发现存在标签时间错误的旧加工版本，必须标为历史结果。
- causal_input_v1 的源 train/val、内部 test、Real 角色数据分开管理；不要把源 val、内部 test 和 Real 混成同一验证集。

## 7. 后续维护规则

### 7.1 新实验开始前

1. 先搜索本台账和相关日期目录，确认相同假设、数据、模型和判据是否已经做过。
2. 如果是新实验，先提交冻结协议 JSON 和解释文档，再开始正式运行。
3. 同时在本台账第 3 节新增一行，状态写为“协议已冻结·待运行”；记录配置路径、输入数据版本、seed/fold 和预定判据。
4. 只有正式训练/分析启动后才改为“运行中”。CPU smoke、preflight 和 pytest 不得标成正式实验完成。

### 7.2 实验结束后

1. 保存原始结果报告、机器可读 evaluation、运行日志和必要的身份/哈希证据。
2. 本台账更新为“已完成·通过”“已完成·未通过”或“已完成·描述性”，写明实际运行次数、冻结 verdict、关键数值和证据范围。
3. 原始冻结协议不因结果不好而回改；修正协议时新建 revision，并记录修订发生在正式运行之前还是之后。
4. 失败实验、负结果和执行偏差保留，不删除、不改写成成功。
5. 如果数据版本、标签或任务定义变化，旧实验标记为历史/被替代；不能把旧结果静默迁移到新数据版本。

### 7.3 文档分工

- 本文：文档导航和实验台账。
- `项目进程.md`：项目背景、管理决策、结项安排和项目级任务。

- 每份冻结配置：保留事前约定的样本、流程、判据和禁止事项。
