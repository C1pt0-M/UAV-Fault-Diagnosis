# S 组结构消融冻结协议 v1（MSTCA）

日期：2026-11-06。状态：**运行前冻结**。机器可读版本：`configs/experiments/s_ablation_mstca_v1.json`（以 JSON 为准，本文只解释设计理由）。

## 1. 要回答的问题

|臂|结构|问题|
|---|---|---|
|S0|完整 MSTCA（`mstca`）|参照|
|S1|去 SE（`mstca_no_se`）|SE 是否必要|
|S2|三路都改为 k7（`mstca_single_k7`）|多尺度是否必要|
|S3|参数匹配 CNN1D（`cnn1d_matched`，74/121/128，105929 参数）|MSTCA 是否优于简单 CNN|

KG 相关臂（原设计中的 S4–S6）不再做。放弃 KG 的依据是公式语义错误和门控捷径，已在 `KG-MSTCA结构审查与消融设计_v1.md` 中说明，不需要再用训练结果证明。

## 2. 与历史实验相比的关键变化

|项|历史 M0|本协议|理由|
|---|---|---|---|
|初始化|seed42 来自 KG 构造后映射；其他 seed 现场构造 KG|`ablation_factory` 的 `module_seed_v1`，所有 seed 统一|同 seed 下各臂公共层逐位相同（已有 golden 测试）|
|选点|完整源 val 的 Macro-F1|训练折内按关联组留出约 10% 组（inner），用类平衡交叉熵选点|val 不再同时承担选点和评估；交叉熵是与阈值无关的恰当评分，不会像 Macro-F1 那样偏好"悬停即报故障"的轮次|
|评估|val 或单 seed 留出折|3 seed × 3 外层折，汇总全部 162069 个 train 窗口的留出预测|每个窗口都由没见过它所在折的模型预测|
|主指标|阈值 0.5 下的计数|召回固定为 97% 时的正常误报数（FP@R97）|不同结构的概率校准不同，固定阈值比较不公平；97% 约等于历史 M0 在留出折上 0.5 阈值的召回（97.2%）|

外层折沿用 `h1cv` 规则（与 feature_groupcv_v1、ens_groupcv_seed43_v1 相同），所以 S 组的留出预测之后可以直接和已有的 GBT 留出预测配对，用于 R 组的融合实验。

## 3. 判读规则（结果出来前已固定）

- 比较量：每个 seed 的比值 FP@R97(臂) / FP@R97(S0)，三个 seed 取几何平均。
- 不确定性：按关联组做 cluster bootstrap 2000 次，各臂、各 seed 使用同一组重采样，每次重采样都重新计算 97% 召回对应的阈值。
- 非劣效边界：1.10（最多比 S0 多 10% 的误报）。

|臂|结论|条件|
|---|---|---|
|S1/S2|组件有用|比值 95% 下界 > 1.0|
|S1/S2|组件可去掉|比值 95% 上界 < 1.10，且各故障类召回下降不超过 1 pp|
|S3|MSTCA 更好|S3/S0 比值 95% 下界 > 1.0|
|S3|MSTCA 无优势|上界 < 1.10，且类约束成立|
|任何臂|不确定|其他情况；或 3 个 seed 中少于 2 个方向一致；或 AP 的区间方向与上述结论相反|

悬停超过 30 s 的独立正常段只单独报告，不能一票否决（沿用 m0s_stats_branch_v1）。

**对论文表述的影响**：
- S1 若为"组件有用"，可以写"SE 有效"；若为"可去掉"，论文不能声称 SE 的贡献，后续可考虑简化模型。
- S2 同理，对应"多尺度"。
- S3 若为"无优势"，论文不能声称 MSTCA 在结构上优于 CNN，只能把它作为"性能相当的基线"。

## 4. 两个阶段

1. **阶段 1（交叉验证）**：36 次训练。按 seed → 折 → 臂的顺序执行，每个 seed 跑完 12 次才算一个完整单元。全部完成后计算结论，写入结果文件并记录 SHA256。
2. **阶段 2（val 确认）**：结论固定后，4 臂 × 3 seed 共 12 次，在全部 train（去掉 inner）上训练，对 34710 个源 val 窗口只预测一次。val 只能"确认"或"未确认"，不能改变阶段 1 的结论。

内部 test 和 Real 在本协议中都不使用。

**预算**：历史 M0 留出折训练每次约 6–7 分钟（4090D，53–69 轮）。48 次约 6–8 GPU 小时。

## 5. 训练前必须通过的检查

1. `ssh autodl_UAV` 可连接；正式环境为 torch 2.5.1+cu124、numpy 2.1.3。
2. 在正式环境运行 `tests/test_mstca_ablation_factory.py`，12 个 golden digest 全部一致。**不一致就停下报告，不得重新生成 golden 值**——不一致说明两个 PyTorch 版本生成的初始权重不同，需要先决定处理方式。
3. 协议 SHA 锁、代码 SHA、9 个数据文件 SHA 全部吻合；外层折和 inner 的窗口数与协议一致。
4. GPU 确定性：S0 seed42 fold0 从头训练 2 轮，重复两次，状态 digest 必须相同。
5. 本地 CPU 冒烟测试已经通过（每臂 2 轮、不超过 2048 个窗口）。
