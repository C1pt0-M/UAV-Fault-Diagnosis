# Real 目标域正常适配：一次性探索性测试

日期：2026-11-06。协议：`configs/experiments/real_normal_adapt_v2_test.json`（读取 Real 测试集前冻结）。脚本：`scripts/research/real_normal_adapt_test.py`。产物：`artifacts/real_normal_adapt_v2_test_20261106/`，已写锁文件。Real 测试集之前已被查看过，本次属于探索性评估，也是这条线上最后一次使用 Real 测试集。

## 设置

- 测试的两个臂来自[开发阶段](real_normal_adapt_v2_dev_results.md)：
  - **GBT_D2**：重拟合时加入 adapt_normal 窗口的 GBT，使用原始输入。
  - **GBT_D3**：同样的 GBT，Real 输入先做仿射对齐。
- 两个臂的 onset 都事先定为 0.75，事件规则和统计口径与 `real_event_eval_v1` 相同。
- 参照组直接取 `real_event_eval_v1` 已有的结果，没有重跑。

## 判读

按事先定的判读规则，新确认召回远低于 M0@0.70，并且低于 50%，所以判定为：**加入目标域正常后，GBT 学到的是"Real 的样子就是正常"，而不是故障与正常的差别。**

- 误报几乎全部消失，但只有 4–6% 的故障窗口仍能被检出。新确认的 41 和 51 个案例主要集中在 waypoint 和 circling 的 motor 故障上。
- 这与开发阶段的补充探查一致：用同样的特征区分源和 Real 正常，AUC 是 1.0。
- 前一轮源域上的 M0/ENS 在 Real 上是"全判故障"，这一轮是"全判正常"。两种情况都说明，现有特征下，Real 的故障和 Real 的正常在分数上没有分开。

## 结论

1. 用 SIL/HIL 源监督训练，再加 Real 正常数据适配，这个方案在因果版 Real 上没有成功：要么误报约 94%，要么故障召回约 10%，没有可用的中间点。
2. 原因是源域和 Real 的数据差异远大于故障本身造成的变化，Real 的正常波动比仿真大 2–7 倍。没有带标签的 Real 故障数据，就无法学习 Real 域里的故障边界。
3. 这条线在 Real 测试集上不再做任何调整。如果后续还想做跨域，需要换一种做法，例如加入少量带故障标签的 Real 训练数据（需要重新划分，并与现在的测试集严格隔离），或者使用对波动幅度不敏感的特征。这些都要新立协议。
