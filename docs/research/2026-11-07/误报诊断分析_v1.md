# 误报诊断分析（v1）

日期：2026-11-07。
数据：train 上 T0（inner CE 早停）的 CV 留出预测（`artifacts/t_selection_mstca_v1/cv/`，5 seed × 3 fold，覆盖全部 162069 个窗口），以及 `cache/train.pt` 中未归一化的原始输入。
脚本和完整输出：`artifacts/false_alarm_diagnosis_v1/`（`diag1`、`chan_shift`、`chan_prof`）。
没有使用 val、internal test 或 Real 数据。本文是描述性分析，没有预注册的判定。

## 1. 误报集中在哪里

工作点为 R97，以下数字是 5 个 seed 的平均。

- 95.3% 的误报来自独立正常飞行（`normal_flight`），这些窗口的误报率是 17.8%。故障案例中起始前的正常部分误报率只有 0.3%。
- 334 条独立正常飞行中，276 条至少有一次误报。前 25% 的飞行贡献了 62% 的误报。
- 误报成段出现，所以时间平滑基本无效（见 V 组之后的分析）。

## 2. 误报率随飞行时间上升

每种飞行类型的故障注入时间几乎固定，起始时间中位数如下：

| 飞行类型 | 故障起始中位数 |
|---|---|
| hover | 19.4 s |
| acce / velocity | 22.9 s |
| dece | 24.9 s |
| circling / waypoint | 53.1 s |

独立正常窗口的误报率在这个时间之前约为 0–6%，之后快速上升：

| 飞行类型 | 起始时间之后的误报率 |
|---|---|
| hover | 30–45 s 为 85%，45–60 s 为 92% |
| velocity | 32% → 55% |
| acce | 18% → 46% |
| dece | 9% → 36% |
| waypoint | 60–90 s 为 42% |
| circling | 60–90 s 为 19% |

## 3. 机制：飞行阶段覆盖不足，而不是录制偏移

对每种飞行类型，把窗口分成四组：

- EN：独立正常，起始时间之前；
- LN：独立正常，起始时间之后 5 s 以上；
- PF：故障案例中起始前的正常部分；
- LF：起始时间之后 5 s 以上的故障窗口。

对 26 个通道的窗口均值和标准差，分别计算组间的单变量 AUC。

### 3.1 同一时间段内没有录制偏移（hover 除外）

EN 和 PF 的单变量 AUC：

- acce、dece、velocity、waypoint、circling：都在 0.42–0.60 之间；
- 模型对 EN 和 PF 的平均分数基本相同，例如 acce 为 0.039 和 0.036，velocity 都是 0.044。

所以在相同飞行阶段，独立正常飞行和故障案例的正常部分看起来是一样的，模型也把它们当成一样处理。

### 3.2 后段是另一种飞行状态

LN 和 EN 的差别非常大，单通道 AUC 高达 0.9–0.99：

- acce：速度从约 0 升到约 6 m/s，PWM 从约 1265 升到约 1375，姿态俯仰随之改变；
- velocity：速度从约 0 升到约 3.7 m/s；
- dece：垂直速度和俯仰发生变化；
- waypoint 和 circling：航向（att_q、mag）和速度方向发生变化；
- hover：后段是稳定悬停，相对高度约 0，vz 约 0。

在训练集中，这些后段飞行状态下的样本几乎全是故障窗口：

| 飞行类型 | LN（正常） | LF（故障） | 比例 |
|---|---|---|---|
| acce | 700 | 7076 | 约 1 : 10 |
| hover | 1689 | 18760 | 约 1 : 11 |
| velocity | 1377 | 9357 | 约 1 : 7 |
| waypoint | 574 | 15050 | 约 1 : 26 |
| circling | 318 | 13866 | 约 1 : 44 |

模型并不知道时间。它学到的是"处于这种飞行状态，基本就是故障"。到了 R97 阈值，这些少数的正常窗口就被牺牲掉了。

### 3.3 信号本身部分可分

以 hover 后段为例，LN 的 PWM 中位数约 1265，LF 约 1287，单通道 AUC 约 0.78。所以问题在于先验极度不平衡、正常覆盖太少，不在于信号完全不可分。

### 3.4 hover 有一个额外的录制差异

起飞阶段（0–20 s），独立正常 hover 飞行与故障案例的 PWM 和爬升剖面不同，单通道 AUC 约 0.81：

- 独立正常飞行中约一半的早段 PWM 中位数约 1305；
- 故障案例的早段 PWM 中位数约 1277。

这一点影响对 case-relative 特征的解读。以起飞段为基准的相对化特征，可能借这个录制差异把独立正常飞行区分出来，而不是学到了故障特征。之前 GBT 把 hover 后段误报从 140/280 降到 37/280，这个结果里可能就有这部分作用。

## 4. 结论与下一步

1. 误报的主因是：起始时间之后的飞行状态里，正常样本覆盖不足、先验极度偏向故障。在同一飞行阶段内，独立正常飞行和故障案例之间没有录制偏移，hover 起飞段除外。
2. 最直接的对策是在训练时按"飞行类型 × 阶段"重新平衡正常和故障的权重（阶段平衡加权）。阶段只用于给训练样本加权，推理时不需要时间信息。
3. case-relative 输入对后段飞行状态的覆盖问题帮助有限（正常和故障相对基准的偏移是一样的）。在 hover 上它还可能借用录制差异，所以应降为次要方向；如果要做，需要额外检查它是否只在利用独立正常飞行的起飞差异。
