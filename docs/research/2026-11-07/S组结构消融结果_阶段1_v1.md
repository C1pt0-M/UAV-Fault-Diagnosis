## 4. 观察到的问题（不改变结论，供后续设计参考）

1. **inner CE 选点倾向于早期轮次。**
   - 36 个 run 中有 13 个的 best epoch ≤ 23，fold 1 尤其明显，因此不少 run 在第 50 轮就停了。
   - S0 三个 seed 中，last 权重的 FP@R97 都比 best 低 9–20%。
   - 原因可能是：交叉熵会惩罚后期的过度自信，但这时排序其实还在改善。
   - 后续实验如果主指标是 FP@R97，选点指标应该与它对齐，或者固定训练轮数。
2. **seed 间方差大于结构效应。** S0 的 FP@R97 在 3588–4610 之间，相差 28%。bootstrap 只对关联组重采样，不包含训练随机性，所以 CI 低估了总体不确定性。seed 一致性规则只能部分弥补这一点。
3. **类约束对气压计非常敏感。** 两个 TRADE_OFF 都只由气压计触发，而且只比 1 pp 的阈值多出 0.07 和 0.45 pp。气压计故障主要出现在悬停段，窗口数少，波动大。

## 5. 对论文表述的影响

- **SE：** 不能声称 SE 降低误报；只能说去掉 SE 后 AP 略有下降（约 0.002），气压计召回略降。
- **多尺度：** 不能声称多尺度降低误报。单尺度 k7 的误报反而更少，代价是气压计召回可能略低（在 best 权重下出现，last 权重下没有）。
- **MSTCA 对 CNN：** 只能写"在预先冻结的选点规则下，MSTCA 的 FP@R97 比参数匹配的 CNN 低约 9%（CI 1.05–1.16），AP 一致"，同时必须披露 last 权重敏感性分析中该差异消失。

## 6. 执行偏离（PI 首次回复中没有报告，由架构方核对时发现）

1. **`model_contract.py` 的字节差异。**
   - 冻结 SHA 来自 Windows 工作副本（CRLF），服务器按 `.gitattributes eol=lf` 检出的是 LF。
   - PI 把文件恢复成 CRLF 字节；内容相同，git 工作区干净。
   - 教训：以后的 code pin 应该对换行规范化后的内容取 SHA。
2. **golden 不一致（协议要求停下并报告，PI 没有停下）。**
   - 第一次预检时 12 个 golden 全部失败。服务器 CPU（Xeon 8352S）支持 AVX-512，torch 走向量化分发后，初始化产生的随机数与本地生成 golden 时不同。
   - PI 设置 `ATEN_CPU_CAPABILITY=default` 后，12 个 golden 原样通过；golden 没有被修改或重新生成。
   - 36 个 run 都在这个设置下运行，初始权重与冻结的 golden 逐位相同。
   - 判定：对实验有效性没有影响，但属于流程偏离，在此记录。
3. **测试环境。** PI 用 `--system-site-packages` 建了 venv（`runtime_pytest_r1`）来补装 pytest，torch 和 numpy 版本不变。
