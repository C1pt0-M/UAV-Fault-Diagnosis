# 当前 UAV 数据能支持哪些研究：只读审计

审计日期：2026-10-08。结论：**数据可以继续用于论文实验，优先支持按案例隔离的故障检测、诊断及跨域泛化；严格在线检测需要先修正预处理。当前证据不足以把它直接包装成自然多客户端联邦学习或长期漂移数据集。** 这是数据可行性判断，不是创新性判断，也不据此锁定论文题目或保证期刊分区。

## 1. 检查范围与证据

以 `D:/UAV-Data/splits/rflymad_case_split_v2/rflymad_case_level_split_manifest.csv` 为唯一案例入口，读取清单指定的全部 **6543 个完整案例 CSV**，没有重复统计工作区副本、旧版 HIL 和窗口缓存。核对文件哈希、行列数、时间戳、故障活动标签、26 特征契约的输入可用性，以及原始案例目录和现有分组划分。

另外读取全部 **465 个真实案例的原始 ROS 故障控制日志**，并按“5 种工况 × 7 类有效标签”各取一个案例，共 **35 个真实案例**，对照原始 IMU 的 X 轴角速度与处理后数据。IMU 数值插值结论只覆盖这些抽查通道，不能外推成所有原始通道均已验证。没有训练模型、改变标签/划分、修改源数据或下载 SMD。

## 2. 实际数据规模

| 数据域 | 案例数 | 有故障活动的案例 | 全段无有效故障活动的案例 | 记录时长合计 | 单案例时长中位数 |
|---|---:|---:|---:|---:|---:|
| SIL：软件在环 | 3023 | 2785 | 238 | 63.47 小时 | 69.50 秒 |
| HIL：硬件在环公开数据 | 3055 | 2815 | 240 | 61.43 小时 | 67.88 秒 |

这里的时长是处理后日志首末时间戳之差，尚未逐条验证实际离地时间。HIL 是已有公开数据，不代表项目拥有硬件实验设备。案例之间可能共享仿真场景或采集条件，6543 也不能简单视为完全统计独立的样本数；高度重叠的数百万窗口更不能这样理解。

真实故障案例为：电机 223、加速度计 24、陀螺仪 35、磁力计 36、气压计 42、GPS 32。真实数据没有当前仿真中的螺旋桨、低电压、风扰、载荷等类别，因此这些仿真开放集类别的结果不能直接称作真实场景开放集验证。

REAL 的 73 个有效正常案例中，48 个原本为无故障飞行，25 个来自原故障案例的保留正常片段。本次对照确认：这 25 个原始控制日志中存在故障指令，但都在当前保留 CSV 时间范围之外；它们不是 25 次新增独立正常采集。其中 5 个片段只有 3 秒，几乎不能用于评估检测器热启动后的行为。基于控制标志的“正常”也不等于已证明所有物理状态正常。

## 3. 质量与版本核查

全部 6543 个 CSV 可读取；源案例目录均存在。未发现重复案例 ID、重复处理路径或字节完全相同的文件。字节不重复不代表不存在近重复场景。

时间戳均递增，全部符合 50 Hz 的 20 ms 网格，未发现非有限时间戳。26 个契约特征均可构造，未发现缺失或非有限数值：其中 25 个从原始通道映射，`acc_norm` 由三轴加速度计算；它没有同名源列是正常设计。审计统计尚未执行每窗口相对气压高度转换，不能直接把统计值当作已处理的模型输入。数值完整也不意味着采集连续：插值可掩盖原始采样间隙。

所有案例的正常/故障活动状态都与当前契约一致；真实有效故障 ID 的子类型也与契约一致。未发现未知或非整数标签。不过，这只验证处理后标签的内部一致性，不能替代原始事件检查。

**确有一个全量版本问题：3055 个 HIL 文件全部与当前划分清单中的旧哈希不一致。** 逐项对照后，3055 个现存文件的哈希均与 2026-08-13 的 HIL 重处理日志一致，且行数、列数与划分清单一致。契约注明此次重处理将速度通道从设定值改为实际速度。证据支持“数据已更新、划分清单哈希未同步”，没有证据表明文件损坏。

后续需另外生成注明版本的文件索引，保留旧索引，并核查训练副本、归一化统计、窗口特征缓存是否来自同一版数据。本次没有验证现存缓存及已训练模型的版本一致性，也没有直接覆盖这些资产。

## 4. 严格在线评估的主要问题

处理日志指向 `D:/RflyMAD/Data_processing_tools`。该目录的 `Rflytool_main.py` 调用 `fileprocess.py::freq_adjustment`，后者使用默认线性 `interp1d`；故障 ID 修复函数还会在特定条件下向后寻找有效 ID。

本次不仅查看了代码，还进行了数值对照：35 个抽查案例的 X 轴角速度，在原始时间范围内的全部被检查网格点，都与线性插值结果在规定容差内吻合（`atol=1e-7, rtol=1e-6`）。这意味着在原始采样点之间，处理值依赖后一个观测。

- 各抽查案例中，“后一原始采样点比当前网格时间晚多少”的第 95 百分位为 **5.58–7.09 ms**。
- 抽查中最大值为 **234.48 ms**；原始 IMU 采样间隙最大为 **241.12 ms**。
- 这些是数据可用性时间差，不是模型推理耗时，也尚未证明会令某个模型指标改善多少。

因此，直接顺序回放当前 CSV 可以称为回顾性流式评估，但不能在不说明预处理延迟的情况下证明严格因果在线检测。若要报告在线延迟，应从原始流重建只使用当时已有样本的处理流程，或明确引入等待未来样本的缓冲延迟并计入总延迟。

故障标签也存在边界变化：391 个可按顺序等数量配对的故障案例共 888 个活动区间起点，处理后起点减去原始 ROS 故障指令起点，范围为 **−27.25 到 +13.63 ms**，中位数 **−2.29 ms**；543 个处理后起点较早。这一参照是记录到的故障指令时间，不是独立测量的物理损伤发生时间。

另有 `REAL/circling/motor/343_1`：原始保留时间范围内有两个活动区间，中间夹有一个短暂非活动控制记录，处理后合成了一个连续区间。不能只用“是否出现故障 ID”断言事件边界完全保真。

真实数据中有 **51 个电机案例包含多个故障活动区间**。它们可能对应同一次实验中的重复注入；短暂关闭标志不能直接解释为物理状态已完全恢复。后续应明确按“整次注入实验”还是“每次活动区间”评价，并报告选择，不能把这些区间都当作独立飞行样本。

原始 ROS 工况日志另有 8 个 CSV 无法被严格解析，原因是部分行字段数异常；原始故障控制日志 465/465 均读成功。8 个错误被记录而未跳行修补。其余日志中常见 `[0,1,4,9]`、`[0,1,4,11]` 等状态序列，说明存在控制阶段变化，但尚未核对每个状态的物理定义，不能据此宣称已具备长期概念漂移标签。

## 5. 连续正常数据是否足够

| 数据域 | 故障案例中，首个故障前时长中位数 | 至少一段连续无活动标志 ≥60 秒的案例 | ≥120 秒 | ≥300 秒 |
|---|---:|---:|---:|---:|
| SIL | 26.92 秒 | 82 | 0 | 0 |
| HIL | 25.24 秒 | 71 | 0 | 0 |
| REAL | 35.32 秒 | 47 | 17 | 0 |

以上连续片段包含全正常记录、故障前和故障后的非活动区间；使用故障后的片段时，仍需排除残留影响，不能直接当作健康适应数据。REAL 全段无有效故障活动的 73 个案例合计仅 **1.40 小时**，最长约 **184 秒**。分散在很多飞行中的正常总时长不能替代一条长时间连续运行记录，也不足以精确验证很低的每小时误报率。

这足以支持短时故障检测试验，尤其是“发生后多久报警”。它尚不支持自然的数小时/数天漂移与设备老化叙事。把独立飞行拼起来可构造受控工况切换实验，但必须标明人工拼接，并规定边界处是否重置状态；不能称为原始连续运行。

“故障发生前预测”也应单独审查。当前标签主要反映注入命令，故障前不一定存在可观察的退化前兆。对固定注入日程的学习可能只是在识别飞行阶段。移除时间戳输入不足以完全消除这个问题，仍需要工况匹配的伪起点对照等检验。

## 6. 各研究方向的可行性

| 候选任务 | 当前判断 | 主要边界 |
|---|---|---|
| 按飞行案例隔离的故障分类/诊断 | 可行 | 类别不平衡；以案例/配对组统计，不随机混分重叠窗口 |
| 仿真到真实的泛化 | 可行 | 保留 REAL 的独立评估角色；某些故障只在仿真中存在 |
| 正常数据训练的异常检测 | 可行，值得先做小试验 | 现有训练集中有 334 个完整正常案例；阈值需独立校准 |
| 流式故障检测与检测延迟 | 有条件可行 | 先解决因果重采样、标签起点与重复活动区间定义 |
| 故障发生前预警 | 目前证据不够 | 注入前不一定有退化信号，需排除飞行阶段/注入日程捷径 |
| 长期漂移下持续适应 | 不适合作为当前唯一主数据集 | 连续记录较短，长期自然变化和生命周期依据不足 |
| 自然多客户端联邦学习 | 当前未建立依据 | 清单没有稳定设备 ID；SIL/HIL/REAL 是数据域，工况是任务状态，均不自动等于设备客户端 |
| 机器学习优化相关研究 | 数据层面可以承载，尚未形成具体问题 | 应先验证稳定存在的优化困难，再研究算法，不能把常规训练改名当创新 |

没有实体无人机并不妨碍用公开真实飞行日志验证算法。论文应准确表述为公开数据上的回顾性实验；它不能代替新采集飞行、板载实时部署或硬件在环实测。

## 7. 建议的下一步：先把评估做可信，不急着定题

1. **固定数据版本。** 生成与当前 HIL 匹配的新索引并检查关联缓存；保留原始数据与旧索引。不要把更新数据哈希和改变训练/测试成员混为一件事。
2. **做小规模因果重采样试验。** 从原始 IMU/控制等必要通道开始，以当前网格为参照，使用历史样本保持或明确的因果聚合；记录样本年龄和长间隙。故障活动标签用原始控制消息的阶跃变化，另行规定短间断如何计数。比较修正前后的数值及事件边界，确认差异后再扩大处理范围。
3. **建立轻量基线，先找真实困难。** 例如正常数据的 PCA 重构分数和一个小型时序预测模型。训练与阈值选择使用现有 train/val；逐完整案例回放并重置状态，至少报告检测率、漏检、误报次数/正常曝光时长、检测延迟分布及每类结果。延迟必须同时给出漏检比例，不能只统计容易检测的成功案例。按案例或仿真配对组做不确定性估计，不把重叠窗口当作独立重复。
4. **遵守现有外部测试协议。** 465 个 REAL 目前全部是 `external_test`，现有协议禁止用它们训练、归一化拟合、调阈值或选模型。质量核查没有拟合模型；若以后研究测试时适应，需要事先另定协议、开发集和适应规则，不能边看这批结果边调方法，再称作零样本外部测试。
5. **与 SMD 比较后再收敛方向。** 如果侧重长期多变量序列或以机器为客户端的分布式学习，SMD 值得核对具体文件、设备划分、时间长度和训练标签。它有机器划分也不自动证明联邦学习具有必要性；还需说明为什么数据不能集中、异构性是什么，以及相对本地/集中训练的研究问题。当前不下载、不训练 SMD。

如果基线结果显示主要困难来自数据预处理或类别覆盖，先解决实验问题；如果存在稳定、可复现且已有方法未解决的失效，再围绕它做文献核对和方法设计。数据质量修补是论文基础，通常不能单独作为方法创新。

## 8. 复现入口

在项目根目录运行：

```powershell
python -X utf8 -u scripts/research/audit_data_feasibility.py
python -X utf8 -u scripts/research/audit_raw_timing.py
python -X utf8 scripts/research/summarize_data_feasibility.py
```

首项会重新读取全部当前案例，约需数分钟，可能需要外部数据目录的读取权限。三个脚本只写本研究输出目录。本报告以 `full_*` 结果为准，早期 `pilot_*` 为中间抽查产物，不应用来替代全量结果。

## 9. 同日基线实验后的补充发现

运行基线并检查案例后，对本轮验证/测试的 555 个 HIL 案例追加了只读核查。在两个事件标志均激活的 471 个案例中，`UAVState_data_fault_state` 起点减去故障控制 ID 起点的差值中位数为 +0.68 秒，范围 −20.66 至 +4.00 秒；另有 12 个案例状态标志激活而控制 ID 未激活。两个处理后事件来源存在明显分歧，尚不能据此确定物理故障起点或差异根因。

这不否定上文“选定活动列与案例标签内部一致”的统计，但说明内部一致不足以证明事件时间正确。严格在线检测、提前预警和延迟比较需要先核实此问题。详见 [第一轮基线结果](../uav_baselines_v1/第一轮基线结果.md) 与其中的逐案例对照。
