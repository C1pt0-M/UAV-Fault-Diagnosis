# M0-matched 与 M1 Balanced：同窗口预测差异

**结论：**M1 Balanced 在相同的32,381个 source-Val 原窗口ID上，纠正了部分正常误报，同时增加了故障漏检。它不是“新增漏检124窗”这么简单：**192窗由M0检出变成M1漏检，68窗反向恢复，净增124**；正常侧**纠正166个旧误报、新增29个误报，净减137**。四维残差分支对两种变化都可能起直接作用，但完整变化还包含训练后26维编码器／分类头的变化；仅凭本次观察无法证明哪一个物理分量是根因，也不能声称目标“保持故障检出能力”已经实现。

范围与身份：只用已完成的`M0_matched/balanced_source_normal`、`M1/balanced_source_normal`两组best对应的source-Val预测、M1全150帧有效残差sidecar、冻结原窗口ledger，以及仅作背景参考的74,700个source-Train正常窗残差（不重拟合归一化或选择阈值）。先以`original_cache_index`唯一原ID对齐并核对label、base compact index、哈希、来源Val；固定原分类阈值0.5（历史`argmax`，无tie）。无新训练、阈值／模型选择、最终Test／Real、数据／权重修改。两组都从同一Balanced历史M0 best公共参数开始，但各自继续训练且M1多3,168参数；Val已用于选best，不是盲验证。

## 3. N1～N4 与直接分支贡献

以下为每窗150帧**物理值中位数**，不是对测试数据再训练的尺度；N1单位m，N2～N4／姿态范数单位rad。P10–P90与每案例等权中位数、四个signed分量、P95、std及源Train正常同SIL/HIL×工况百分位都保存在`results/feature_summaries.csv`／`summary.json`，避免只选均值来解释。

|窗口组|N1绝对幅值中位(m)|N2/N3/N4绝对幅值中位(rad)|姿态范数中位(rad)|联合Train-z RMS中位|
|---|---:|---:|---:|---:|
|新增漏检192|0.03108|0.000097/0.000116/0.000059|0.000215|0.489|
|恢复检出68|0.03224|0.000082/0.000170/0.000084|0.000268|0.505|
|双方检出15,904|0.03014|0.000115/0.000121/0.000099|0.000266|0.519|
|纠正误报166|0.03329|0.000091/0.000101/0.000056|0.000201|0.506|
|双方误报306|0.03065|0.000095/0.000098/0.000052|0.000191|0.479|
|新增误报29|0.03655|0.000091/0.000095/0.000068|0.000208|0.567|

**观察：**新增漏检的姿态范数中位较双方检出低（0.000215 vs 0.000266rad），但N1及四维联合幅值广泛重叠；不是“残差均为零”。按相同域／工况的源Train正常窗定位，新增漏检姿态范数窗中位百分位约0.226，GPS约0.223，陀螺仪约0.214；GPS新增漏检53/71个窗口低于对应Train正常窗姿态范数第50百分位。可是这并非足以判别故障的物理阈值：源Train正常来源、运行状态、故障注入强度及窗口相关性均可能影响这些分布。纠正误报的姿态范数中位0.000201rad，也与双方误报0.000191rad接近；没有统一的单分量幅值规则。

为减少案例／阶段混杂，再为新增漏检找**同一案例、同phase、原M0概率最近**的双方检出窗；187/192可找到（对照可能被重复使用，端点时差中位5.3s）。新增漏检减对照的N1绝对幅值中位−0.000506m，姿态范数中位−0.00000123rad；差值P10–P90跨零。纠正误报与同案例、同正常前后30s段、M0概率最近的双方误报窗仅142/166有配对（端点差中位3.2s），N1差中位＋0.00135m，姿态范数＋0.00000394rad，分布也跨零。该对照是描述性的，非随机／严格运动背景匹配，不支持单独用N1或范数解释效果。

**模型内部可精确确定的部分：**M1 eval时dropout关闭，残差adapter输出与26维编码器128维特征相加后接线性head。读取已保存M1 best的adapter／head，直接计算其对“故障logit－正常logit”的贡献，并从保存的M1概率log-odds中扣除；全部455个预测改变窗口的残差和预测身份已独立复核。

|结果|直接残差分支贡献<0|移去该直接贡献则M1在故障侧，加入后跨为正常|M1共同路径本来就在正常侧|
|---|---:|---:|---:|
|新增漏检192|143|105|87|
|纠正误报166|105|84|82|

这**不是**“105个漏检／84个误报已被物理特征因果证明”：adapter包含学习的**固定输出bias**，其故障margin贡献约−0.576，且M1的共同编码器／头也经过不同优化。直接分支贡献可以**压低原本应检出的故障**，也可**压低正常误报**；它并不是“总让健康得分更安全”，因为新增漏检有49窗直接贡献≥0、纠正误报有61窗直接贡献≥0，靠共同路径变化也能翻转。68个恢复故障中只有10窗由正向直接贡献单独跨过M1分类边界。此分解只给模型内部的代数定位，不能作独立的单轴特征消融，更不能推断真实故障机理。

## 4. 正常误报改善发生的场景

纠正的166窗中159窗来自**独立正常日志**、7窗来自故障案例的故障前正常部分；新增的29个正常误报中分别28／1。来源对应的独立正常hover，**95窗被纠正、3窗新增**（SIL 51／1、HIL 44／2），净少92窗；其中独立正常hover后30s纠正61、增加3，净少58，和前轮220/280→162/280一致。前30s纠正34、新增0。

全部正常窗按场景：hover纠正98／新增3、velocity 25／11、dece 23／5、waypoint 13／0、acce 6／10、circling 1／0。可见改进以hover为主，但加速段反而净多4个误报；不同正常工况尚未得到一致收益。场景名为日志目录，hover中仍可出现爬升／稳态过程，不等于每窗都已物理悬停。

这批纠正误报M0原概率中位0.537、M1中位0.465；157/166原M0<0.6。四维残差对分数的直接贡献有时为正，例如典型SIL正常hover窗口3991直接贡献**＋0.346**（偏向故障），但M1共同路径变为正常侧；HIL正常hover窗口21821直接贡献**−0.405**且把共同路径从故障侧推过边界。这正说明不能将所有减少的误报归因于“残差较小就正确识别为正常”。

## 6. 答案与不能推断的部分

当前最有支持的**工作解释**是：共同正常hover样本中大量本来靠近0.5的误报被整体M1函数推向正常；同样的改变也使部分接近0.5且运动学上较“自洽”的真实故障窗被推向正常，GPS／陀螺仪和部分电机故障尤其存在这种风险。**这是对观察到的配对预测、幅值重叠和模型margin的描述性解释，不是证明了“残差越小模型越判正常”、每个故障目录的机理、或某轴对决策的因果责任。**加速度计velocity案例甚至存在正向残差贡献仍漏检，故不能用单一“低残差”叙述所有错误。

剩余不足：Val已被反复用于开发，单seed且窗口重叠、SIL/HIL配对；记录的目录／标签未完全匹配注入强度、真实姿态／控制器状态及物理损伤时刻。同案例相近M0概率的描述对照也有重复使用且未匹配完整动态。因此不能推出哪一个N1～N4在真实飞行中“发挥作用”或“产生负面影响”，更不能凭这一轮给新阈值／新架构的性能承诺。仅能确认**现有M1组合及其学习结果在这些Val窗上何时有益、何时有害**；最终Test／Real仍隔离。
