# 无人机故障检测替代数据集：第一轮公开资料检索

日期：2026-10-30。[返回项目进程](../../../项目进程.md)。承接[当前RflyMAD加工版本适用性审计](rflymad_dataset_suitability_audit.md)。

> **阶段安排更新：**用户将更换数据集及配套重构／重训留到论文阶段，不纳入当前大创结项。本文保留检索事实和后续研究建议，不作为当前立即下载／切换／开训清单；当前优先级以项目进程为准，已知数据限制仍保留。

**结论：有替代候选，但本轮没有找到能无改动保留“仿真正常／故障监督＋目标域仅正常适配＋真实飞行评估”的直接替代品。**若重点转为真实飞行正常误报／状态异常，优先核对UAV-SEAD；若重点为带注入时序的传感器故障，优先核对BASiC。TLM含动力与传感器异常，但飞行分组和数据来源细节尚待审；ALFA适合作事件检测参考，但平台是固定翼。

本轮只读官网、数据论文HTML、作者README、公开处理代码和仓库元数据；**未下载飞行记录／数据压缩包、未训练、未切换主数据集、未修改旧协议或部署**。这里是资料初筛，不是数据质量验收，不承诺新数据集一定更干净或能得到更高分。

## 1. 候选概览

| 数据集 | 已核对的数据性质／规模 | 正常与故障／异常 | 对当前任务的主要限制 |
|---|---|---|---|
| [UAV-SEAD](https://huggingface.co/datasets/aykutkabaoglu/UAV-SEAD_State_Estimation_Anomaly_Dataset) | 真实多旋翼；1396日志、52:20:05；900正常日志、38:24:19 | 自然发生的状态估计异常，机械／电气、外部定位、全球定位、高度4类 | 标注为异常关注区域，不定义精确起止；不是仿真／真实配对，不等同电机＋传感器注入真值 |
| [BASiC](https://zenodo.org/records/8195068) | ArduCopter SITL；70任务、7小时21分；约1小时4分完整无故障飞行 | GPS、RC、加速度计、陀螺仪、罗盘、气压计6类；10场景，每场景6故障＋1正常 | 纯仿真、无电机故障；加工CSV用了线性插值，不能直接认定严格因果 |
| [TLM-UAV](https://github.com/FishLuYu/TLM-UAV-Anomaly-Detection-Dataset) | 作者说明为SITL，提供GitHub Release和Kaggle入口 | 正常、GPS、加速度计、engine、RC共5标签 | 首轮未核实独立飞行ID、事件起点、规模及数据许可；不能只凭融合CSV直接作为主基准 |
| [ALFA](https://theairlab.org/alfa-dataset/) | 真实固定翼；47条处理后序列；CSV／MAT／ROS bag＋原始日志 | 发动机失效、控制面卡死等，含No Failure条目；官网提供故障类型／时间 | 固定翼而非多旋翼；并非传感器故障全集，正常总量有限，同次飞行可能拆成多个序列 |
| [DronePropA](https://data.mendeley.com/datasets/ftdyxrr3c5/1) | 真实室内四旋翼；130实验、5轨迹、2速度；论文称1 kHz、4.22 GB MAT | 桨叶边缘切口、裂纹、表面切口；每类3严重度＋健康 | 是桨叶损伤，不应改名为电机故障；换装损伤桨叶后采集，不能默认有飞行中动态起点 |
| [UAV-FD](https://zenodo.org/records/7648996) | 真实六旋翼；仓库可见6个NO_FAULT与12个FAULT命名记录，约879 MB | 桨叶破损，含IMU、控制、估计及实际电机转速 | 主要是桨叶／执行器损伤，非传感器故障；独立飞行组和动态起点需看实际文件 |
| [UAV-Realistic-Fault-Dataset](https://github.com/tiiuae/UAV-Realistic-Fault-Dataset) | 真实室内任务，覆盖起飞至降落；加速度、陀螺仪、音频 | 0至4个损伤螺旋桨，含正常类 | 首轮作者README未给清楚总任务数／采样率／事件起点，不据第三方高准确率优先选用 |

“记录数／文件数”不等于独立飞行数；不同格式副本和同次飞行切片不能重复计算。表内规模来自论文／作者描述或明确标记的仓库元数据，未做数据文件级核验。

## 2. 优先候选及需要接受的边界

### 2.1 UAV-SEAD：最值得先查真实正常运行与误报

来源：[论文HTML，尤其IV-B及VI节](https://arxiv.org/html/2602.13900v1)、[数据卡](https://huggingface.co/datasets/aykutkabaoglu/uav-flight-anomaly-dataset/blob/main/README.md)、[已标注文件仓库](https://huggingface.co/datasets/aykutkabaoglu/UAV-SEAD_State_Estimation_Anomaly_Dataset/tree/main)。

优点：

- 正常日志900条、约38.4小时，能为正常运行误报评估提供比当前短片段更充分的候选曝光；是否有长连续正常任务仍需实际统计，不能用总时长代替单次连续时长。
- 有原始ULG及CSV，论文涉及6种多旋翼配置，包含多种传感器与估计量。
- 已核对公开元数据：1396个CSV与1396个ULG，是两种格式，不是2792次飞行；附有`mapping.json`。仓库公开、无访问门槛，许可CC BY 4.0，页面标注约17.8 GB。

重要限制：

- 论文明确说标签 **“not intended to define exact anomaly onset or offset times”**，是异常区域关注标注。它适合研究真实日志异常识别和误报，但**不能把标注边界直接作为毫秒级真实故障起点**。
- 标签由专家结合实际观察、估计状态及多源物理关系进行语义标注，不是受控故障注入的独立物理损伤真值。
- 141条`Uncategorized`记录有异常迹象但未确定类别，不能因为没有明确类型就全部当正常。类别统计有重叠，不能简单相加为独立日志总数。
- 原始数据跨设备，但文件能否可靠对应机体／配置、如何按日期和场景隔离，尚未验收；不能只因为论文提到6种配置，就直接宣布具备可用跨设备划分。
- 作者工具`ulog2csv.py`的同步函数使用`np.interp`；其公开代码本身也有依赖后续观测的线性插值风险。**不能从“换了数据集”推导出“CSV已经严格在线可用”。**这只是代码核对，尚未数值验证发布CSV究竟采用了哪个版本／配置。

处理工具核对版本：仓库提交`3e1492fcd388dbb00b96ae2aed6f3ee1c28a00d6`，`preprocessing/ulog2csv.py` SHA-256=`408c35d66d516c01b607675132130b537bf5ef7965bed3b15bb2e1612b483f75`；[同步函数源码](https://github.com/aykutkabaoglu/ulog_annotation_tool/blob/3e1492fcd388dbb00b96ae2aed6f3ee1c28a00d6/preprocessing/ulog2csv.py#L259-L278)。

**适用方向：**真实无人机多变量状态异常检测／正常误报控制。若采用它作为主数据集，需要先确认允许调整原“仿真到真实”的研究设定，并重新定义标签不确定性下的事件指标；暂不自动作此决定。

### 2.2 BASiC：传感器故障任务更清楚，但不能写成实飞

来源：[数据论文全文HTML](https://pmc.ncbi.nlm.nih.gov/articles/PMC10831493/)、[Zenodo](https://zenodo.org/records/8195068)。

- 10个场景，每个场景运行6类故障任务及1条正常任务，合计70；论文描述注入时刻随机化，而非全部固定在同一飞行日程。
- 约3:02故障前、3:15故障后、1:04完整无故障数据；保留DataFlash二进制／文本、原始日志和加工CSV等。
- 元数据已核对：开放访问、CC BY 4.0；全部格式合计约13.92 GB，其中DataFlash二进制包约577.50 MB，加工数据包约8.42 GB。多个格式是同一批任务的副本。

需进一步审查：

- 明确是SITL仿真，不是70次真实飞行；不包含电机故障，也没有配套真实目标域。
- 论文加工流程使用线性插值和平滑，预处理脚本称可向作者索取；仍需对照原始DataFlash和注入事件验证标签与因果性。
- `Status`是标签；GPS状态、IMU健康位等又参与定义故障。若把标签或等价健康标志原样作为输入，再宣称模型从连续信号发现未知故障，会造成循环论证，须先规定输入和简单状态位基线。
- 场景之间的分组应保留；不能把同一场景高度相似的任务／重叠窗口随机打散后声称跨场景泛化。每场景只有1条完整正常任务，也不能默认适配、校准、正常测试都能按独立日志隔离。

**适用方向：**仿真传感器故障检测／分类与有明确注入语义的事件研究。相较当前RflyMAD，文档中有更明确的场景对照和随机注入描述，但这不是已经验证“更干净”。

### 2.3 TLM：兼有动力与传感器异常，先核对飞行身份再考虑

来源：[作者README](https://github.com/FishLuYu/TLM-UAV-Anomaly-Detection-Dataset)、[Release](https://github.com/FishLuYu/TLM-UAV-Anomaly-Detection-Dataset/releases)、[数据论文DOI](https://doi.org/10.3390/app13074301)。

作者定义0正常、1 GPS、2加速度计、3 engine、4 RC，且明确为SITL。作者另说明`Fusion_Data.csv`经过多传感器融合，并对应另一篇研究，不能与基础记录混淆。

目前README和Release入口可访问，Kaggle页面为动态页面；论文站点本轮直接访问403，未取得并核对全文。**独立任务数、逐飞行ID、注入时序、基础数据与融合数据的关系及许可尚未核实。**不采用第三方随机行划分和高分结果来代替这些核验。`engine`标签也须核实平台和故障机理，不先等同于项目现有多旋翼电机故障。

**适用方向：**候选补充，不因它恰好同时出现动力／传感器标签就直接升为主数据集。

## 3. 其他候选为何不是直接替换

### ALFA：真实事件基准，但固定翼和正常数据量是限制

来源：[官网及逐序列表](https://theairlab.org/alfa-dataset/)、[公开仓库元数据](https://api.figshare.com/v2/articles/12707963)。

- 提供47条处理后序列及原始bag、遥测、DataFlash，官网给出故障类型和发生时间。简介报告约66分钟正常／13分钟故障后数据，原始集合另有更多混合飞行内容。
- 官网表格明确存在`No Failure`条目，不能把47条都当作独立故障飞行。同一原始飞行可能拆成`_1/_2`等序列，分组必须回到母日志。
- 一些故障触发后会立即切换紧急轨迹，需防止只学到控制策略切换，而不是故障本身。
- 元数据：CC BY 4.0、下载未禁用；完整包约1.75 GB，`processed.zip`约272 MB。只是入口与文件元数据核对，未实际下载。

**更适合：**若接受固定翼，作为真实事件检测参考或辅助验证；不是多旋翼电机／传感器全任务的无缝替代。

### DronePropA：多工况桨叶诊断有价值，但跨设备故障验证受限

来源：[论文全文HTML](https://pmc.ncbi.nlm.nih.gov/articles/PMC12136912/)、[Mendeley v1](https://data.mendeley.com/datasets/ftdyxrr3c5/1)。

- 130条实验、5种轨迹、2档速度，3种桨叶缺陷×3严重度；含双IMU、控制量等，论文称1 kHz、约4.22 GB MAT。
- **故障只在D1机体采集，D2／D3只有健康数据**。因此不能据“3架无人机”宣称能完整验证跨机体故障召回；机体与标签分布也可能混杂。
- 研究对象是预先损伤桨叶下的飞行，不是已确认有飞行中故障首次发生时刻的连续注入序列。可以研究滑窗状态识别，但不能默认报告故障发生后的检测延迟。
- 页面可访问，但本轮未核对实际MAT文件清单和数据许可。

### UAV-FD及UAV-Realistic：桨叶损伤备选

[UAV-FD](https://zenodo.org/records/7648996)仓库元数据已确认6份正常和12份损伤命名记录，另有特征表及MATLAB工具，合计约879 MB，CC BY 4.0。18份命名记录不自动代表18个独立实验组，动态起点也尚未核对。

[UAV-Realistic](https://github.com/tiiuae/UAV-Realistic-Fault-Dataset)作者README确认真实室内、起飞至降落、0–4损伤螺旋桨、IMU与音频，但首轮未核实总量、采样频率、许可和逐时刻标签。

**共同限制：**桨叶损伤不能悄悄改名为电机故障；都没有据此建立仿真／真实配对，不优先作为覆盖传感器与动力故障、带动态起点的主基准。

## 4. 暂不优先的近邻

- [多轴振动数据，Scientific Data 2025](https://www.nature.com/articles/s41597-025-05692-4)：外接三轴加速度计、单平台室内定高悬停，发布5个条件文件；论文重复记录叙述与发布文件如何对应仍需核实。适合振动诊断，不是当前完整机载多变量任务的直接替代。
- [外部激光测振数据](https://zenodo.org/records/21203159)：采集设备是机外Laser Doppler Vibrometer，与当前机载遥测实时检测的输入条件不同。
- [UAV Ground Telemetry IDS](https://zenodo.org/records/19086193)：正常／网络攻击通信数据，不等于机械／传感器故障。
- 通用工业轴承、服务器或航班维护数据不因为也叫“异常检测”就替代无人机任务，本轮不按这些方向扩张。

## 5. 建议的下一步，不直接开训

1. **先确认研究边界。**若必须保留仿真到真实及仅目标正常适配，本轮还没有可以直接替换的完整候选；不能默认把BASiC和UAV-SEAD拼接后就成立，还需故障语义、观测通道、坐标／单位及独立成员对齐。
2. **若允许真实日志异常检测：**优先对UAV-SEAD做少量原始日志＋标注映射审计，检查正常曝光、未分类日志、标签区域、缺失通道、设备／日期分组及因果采样，先不做精确物理故障延迟承诺。
3. **若更重视注入事件与传感器任务：**优先审BASiC的原始DataFlash及标签生成；TLM先解决飞行身份、许可及基础数据可用性，ALFA用于接受固定翼情况下的事件参考。
4. **若改成桨叶损伤诊断：**再优先看DronePropA／UAV-FD，而不是沿用当前故障类别和事件指标。
5. 任一路线都先做少量文件可行性核查，再冻结新划分／输入／正常适配角色／评价协议，之后才训练。采样率、故障机理与通道不同，不能默认沿用50 Hz／150帧／26通道或直接复用旧权重，也不能悄悄删掉原任务的故障类别。原RflyMAD缓存和历史成绩保留，不用原Real故障训练或反复择优。

本轮候选主要面向实时二分类，不自动取消离线整日志正常／电机／传感器三分类，也不自动批准新的真实故障监督训练。新数据集的任务与允许用数范围需另行确认。
