# 特征与分支检查：原始时序／门控通路存在明显域敏感性

日期：2026-10-30。先固定 [诊断协议](feature_branch_sensitivity_dev_v1.json)，再执行六个预定探针，约89秒，本地CPU完成。未连接服务器，未训练／更新BN／改部署模型，未读取 Real 校准、最终测试或故障测试数据。

> 后续 [源训练覆盖与无故障悬停检查](source_training_coverage_results.md)已完成，发现源域原无故障悬停后段的严重误报；当前下一步以根目录进程文档为准。

**结论：在允许的10份 Real 正常数据上，原始时序分支经门控后的正向故障贡献明显增加，关系分支平均仍提供负向正常贡献。源模型还对推力/PWM、运动等通道的正常域均值偏移高度敏感；但反向均值矫正未解决正常误判。**这支持继续检查域敏感的表征／门控，而不是继续猜 BN 更新系数，或直接删除关系分支。

这是固定模型的诊断，不是独立目标域验证、新方法成绩或严格物理因果证明。

## 1. 数据和方法

- 原 A0 源模型、源归一化、全部参数及缓冲区保持不变，CPU float32、4线程、确定性执行。
- 源域：完整验证集35520窗口；正常参考用其中17912个正常端点窗口拟合，包含故障前片段。
- 目标域：仅原10份 `adapt_normal` 的640个窗口，全部正常；同样数据既用于拟合参考又用于检查，因此**只能报告样本内正常诊断，不能报告 Real 故障召回或独立泛化**。
- 一次性拟合每通道标准化均值差 `delta = mean(Real适配正常) - mean(源验证正常端点)`，无尺度拟合或系数搜索。
- 每次只平移一个固定通道组：源验证所有窗口加 delta；目标正常窗口减 delta。四组分别为磁力计3通道、控制/PWM8通道、姿态4通道、运动/气压/速度/加速度11通道；另报告全部26通道联合平移和不变基线。
- 两个方向是不同的诊断干预，**不是一个已实现的部署适配方法**。平移还可能打破四元数和派生特征的一致性，不能等同于物理上真实可行的飞行变化。

## 2. 分支分解：不是“关系分支一直在乱报故障”

模型最终为线性二分类头，可逐窗口精确分解故障相对正常的 logit 差：

```text
margin = alpha × raw_score + (1-alpha) × relation_score + bias
正值偏向故障，负值偏向正常；bias = +0.08149
```

这里的两项已经包含原门控权重。alpha 本身不是重要性；门控也由两分支共同决定，不能把代数分解当作独立因果归因或单分支分类器。

| 人群 | alpha中位数 | 原始分支加权贡献均值 | 关系分支加权贡献均值 | 总margin均值 |
|---|---:|---:|---:|---:|
| 源验证正常端点 | 0.292 | +0.322 | −3.010 | −2.607 |
| 源验证故障端点 | 0.978 | +7.008 | −0.228 | +6.861 |
| Real适配正常（样本内） | 0.846 | +4.704 | −2.131 | +2.654 |

三行均值都可与相同bias精确相加重建。完整逐窗口分解已保存并验证。

在这10份 Real 正常中，原始分支／门控状态相较源正常更接近源故障；其正贡献超过关系分支的负贡献，使总分偏向故障。**不能由此说“删除关系分支会变好”——当前关系分支平均恰在提供正常方向的抵消。**也尚不能区分原始编码器与门控各自的独立责任。

## 3. 特征平移敏感性

所有指标均按窗口 argmax 计算；不是事件误报率。

| 探针 | 源验证加偏移后正常误判率 | 源验证故障召回 | 适配正常减偏移后误判率 |
|---|---:|---:|---:|
| 不变基线 | 3.17% | 95.45% | 68.44%（438/640） |
| 磁力计 | 28.50% | 87.68% | 79.84% |
| 控制/PWM | 85.23% | 93.57% | 70.78% |
| 姿态 | 5.38% | 86.42% | 69.22% |
| 运动等11通道 | 70.25% | 93.35% | 61.25% |
| 全26通道 | 45.63% | 94.00% | 79.38% |

- **域偏移敏感性明显。**给源输入加入由正常数据测得的控制/PWM均值差，就使正常误判从3.17%升到85.23%，没有改标签、权重或BN。
- 磁力计均值差虽在此前统计中最大，却不是本组固定探针里引发源正常误判最多的组。不能只按均值差排名认定最重要特征。
- **简单反向对齐不成立。**全部通道反向减均值差后，这640个正常窗口的误判从68.44%变为79.38%；单组也没有恢复可接受判别。
- 这些组同时包含真实故障相关信息。敏感不等于“无用”或“应删除”，不能据此直接裁通道；多组干预也不是可相加的独立效应。
- 单一均值差不能覆盖联合分布、波动、工况／阶段构成和门控的非线性差异；但本轮没有进一步分离这些机制。由于干预可能离开真实数据流形，也不能直接将数值变化归因为已经证明的物理域因果效应。

## 4. 关系分支的语义核查

这些量实际在**源归一化后的通道**上构造，不能作为严格物理残差解释：

1. `actuator_effort` 是标准化控制/PWM均值除以 `clamp(z_acc_norm, min=0.1)`；所有负的标准化加速度模也进入截断区。分母处于不高于0.1区间的帧比例，在源正常中约76.58%，Real适配正常中约50.65%。这不是物理加速度接近零的比例。
2. 该effort代理量的窗口均值再取群体平均：源正常约−1.798，源故障约+1.703，Real适配正常约+0.770。负值并非“负推力”，只是标准化统计代理；域敏感风险存在，但未单独干预它来证明责任。
3. 所谓垂向一致性实际为 `abs(diff(z_baro) - z_vel_z)`：没有将逐样本高度差除以0.02秒，两个通道还使用不同的归一化尺度／基准，不能称为单位一致的垂向动力学残差。
4. 控制与PWM的差，以及标准化四元数向量范数，也应按学习代理量理解，不等于严格执行器误差或物理姿态能量。
5. 三个磁力计通道**没有直接进入9个关系输入**，只进入原始编码器；仍可能通过门控影响两分支的最终加权贡献。单元测试确认仅改磁力计不会改变关系输入。

这些语义问题是代码事实，不代表本轮已证明它们就是全部误报根因。训练时已经使用这些定义，不能在旧权重前直接“改成正确单位公式”然后当成可比较的新模型；若改变定义须新开发协议和训练对照。
