# 源训练／验证集：原始事件与裁剪边界全量核对

日期：2026-10-31。[返回项目进程](../../../项目进程.md)。承接[三域原始资料初核](../2026-10-30/rflymad_raw_source_audit.md)及[加工标签错误审计](../2026-10-30/rflymad_dataset_suitability_audit.md)。

## 结论

> **结论纠正（2026-10-31）：**原始记录支持本地瞬时标签与原始事件时间不一致；40条现有裁剪先于注入也是观察事实，但尚未证实官方边界物理错误或必须延长。候选2秒落地确认不能据此升级为正确方案，暂停推广。最新判断见[官方处理规则复核](official_processing_rule_review.md)。

**原始事件可逐案追溯；标签时间对齐与裁剪范围应分开核验，不能由标签反例推出替代裁剪已正确，也不能据此宣布全库或全部旧成绩无效。**本轮完成全部3135个源train／val案例的事件参考核对及200640个已有抽样窗口对照，未修改任何原始／加工数据、训练标签、缓存、模型或划分，只新增审计脚本、测试、诊断输出及文档。

1. 1338个案例中3914个既有窗口标签与原始GTD末端参考状态不一致，占200640窗口的约1.95%。这不是用模型预测反推的标签。
2. 其中3780窗口的原始GTD与原始ULog命令在窗口末端给出相同状态；余134个分歧窗口落在两种原始参考状态不同的区域，不能全部当作同等确定的物理错标。
3. 旧40条故障在裁剪结束后发生的案例全部复现，含1309个已知提前故障标签。进一步只读复现裁剪函数，确认它们都在`has_low_throttle`变化处提前结束，而当时日志`landed=0`、`ground_contact=0`；全部原始ULog仍有故障后的惯性记录。
4. 3条SIL原始惯性话题时间戳有倒退，未静默排序、未准入为合格连续输入。640个案例的2267个既有窗口跨越超过0.1秒的惯性采样间隙；这是诊断标记，不是冻结的自动删除门槛。

## 1. 精确范围与用数边界

使用原冻结`rflymad_case_split_v2`中的SIL／HIL、train／val、normal／motor／sensor三类案例：

| 集合 | 案例 | 已有cap64窗口 |
|---|---:|---:|
| train | 2580 | 165120 |
| val | 555 | 35520 |
| 合计 | 3135 | 200640 |

平台为SIL1561、HIL1574。没有读取Real、内部最终测试或开放集信号，没有加载模型、查看概率、选阈值或训练；也没有把前次Real原始核对当作新盲测。额外RflySim训练窗口不在本轮范围。

逐案读取原始`UAVState_data.xlsx`中的`uavTime／fault_state`、原始ULog中的`rfly_ctrl_lxl`及` sensor_combined `，核对现有CSV时间网格与既有窗口末端。CSV和TestInfo哈希逐案对照上轮全源记录，路径及冻结成员核对；不调用官方转换入口，不在原始目录产生CSV。

时间参考：GTD毫秒、ULog／CSV微秒均换算成启动时钟秒，再按每个采样时刻取此前最近状态；同一时间戳保留最后一条，不向原始时间覆盖外外推。**该规则是本次诊断参考，不等于已经批准新加工协议，也不保证原始状态是独立物理损伤真值。**

|---|---:|---:|---:|

3914是此次按原始时间戳对照的数值。之前3893是**两种加工后状态列之间**的分歧，1309是原始双流确认的40条特殊案例中的提前故障窗口；三者对象不同，不相互替代，不把3914全部写成相同确定性的物理真值错误。

本次所有200640个窗口的整个时间范围都在GTD原始观测时间范围内；这证明标签参考有时间覆盖，不证明输入没有缺失、不证明异常都可观测，也不等于全部窗口可以直接训练。

2729条同时存在激活的案例中，GTD首次激活减ULog首次注入指令为−0.885979至−0.012秒，中位数−0.079秒。两种记录有语义／记录时刻差异，不能强制逐案平移到完全重合，更不能使用故障检测分数确定起点。

## 3. 新定位：40条的裁剪提前终止

原始工具`fileprocess.py::find_fly_land_time`：先用`ground_contact`找起飞，再把之后首次`has_low_throttle`变化当作结束。**短暂低油门变化不必然等于飞行已经结束**，本次用日志中其他状态交叉检查，不自行把估计器标志当物理真值。

对旧40条逐一调用该函数，只传入从原始ULog读取的内存数组：

- 40／40起点与已有CSV相符；40／40结束点与已有CSV最后一个50Hz采样点相隔一个采样步长以内。
- 40／40结束点`has_low_throttle=1`，但同时`landed=0`、`ground_contact=0`。
- 40／40原始惯性记录在GTD首次激活后继续存在；不等于所有后段通道都质量合格。

示例`HIL/circling/motor/TestCase_10_2300000009`：

| 原始／加工事件 | 启动时钟秒 |
|---|---:|
| 既有裁剪开始 | 35.423780 |
| 工具因低油门变化选择结束 | 63.540224 |
| 现有CSV最后采样点 | 63.523780 |
| 后续低油门恢复 | 64.540410 |
| GTD首次故障激活 | 88.349000 |
| 日志landed恢复为1 | 150.386065 |
| 原始ULog最后时间戳 | 151.043638 |

因此存在两个独立加工环节问题：**裁剪提前结束，丢失故障后段；状态按样本比例重采样，又将后段故障压入剩下片段。**原始后段仍在，为重新加工提供了依据。

现在不能凭这40条就认定所有裁剪提前都由同一原因造成，也不能直接拿故障注入时间延长每条日志——新裁剪应依据飞行状态与必要输入覆盖，不能按模型表现或故障标签挑时段。TrueState全量时钟／信号覆盖尚未补齐，现有26通道是否需要每项GTD资料也要按输入合同明确。

## 5. 清单怎么用

主结果目录：`artifacts/source_event_boundaries_review_20261031/`：

- `case_review_inventory.csv`：3135行逐案例复核原因、原始事件、旧裁剪边界、分歧统计和源文件身份。
- `reference_sample_spans.csv`：原始GTD覆盖的未激活／激活样本连续段，使用行号与首末采样时刻表示；**不是已经批准的新训练有效段**。
- `all_selected_window_diagnostics.csv`：200640个既有窗口末端参考、来源差异、原始惯性质量标记；只作审计，不作为修复后训练标签导入。
- `summary.json`：合并统计及范围边界。
- `independent_verification.json`：独立区间重建、冻结资产身份和旧证据核验。

1475个案例没有触发本报告的特定复核标记，也不表示“1475条全部可训练”；相反，仍需所有输入话题的适用性检查。输入时钟倒退案例的间隙状态在表中明确为未评估，不用空值假装通过。

原始执行产物保留在`source_event_boundaries_full_20261031/`与`source_event_boundaries_remaining_20261031/`。第一批六进程在2651条已写结果后异常终止，未覆盖已有文件；按身份核对仅续查484条，两个进程完成。失败日志、续跑计划、原始脚本快照和不同阶段代码哈希保留，未将部分输出伪装为一次完整成功。

`known_40_crop_diagnostics.json`与`raw_clock_exception_events.json`位于第一批目录。前者只调用原始裁剪纯计算函数，不调用转换器；后者仅补原始事件参考，不认证异常输入。

## 7. 接下来应修哪里

1. **先固定官方裁剪，隔离核对标签。**保留官方流程作为基准，复核原始时钟、标签语义、上游版本及建议依赖环境；不能从固定区间标签不一致直接推出必须改变飞行边界。替代裁剪另需独立依据或作者解释，不按保留故障窗口数量或测试分数选规则。
2. **把质量问题与标签问题分开。**对缺口、时钟倒退明确分段／隔离和记录规则，核查实际需要输入的通道，不插值伪造无缺口实时输入。单纯标签修复可做回顾性对照，但不能宣称已经严格在线。
3. **规则确认后再重建窗口与必要统计、有限重训。**保持案例／仿真配对隔离；任何有效成员变化单独版本化，不用最终测试择优。模型可复用已有MSTCA作受控对照，不再预设保住KG名称。

结项内部完成目标仍为2026年11月15日之前；本轮只完成核对，不承诺上述修复后性能必然达标。
