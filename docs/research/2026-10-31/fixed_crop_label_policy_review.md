## 1. 审核结论

**标签参考方向和既有时间证据保持成立，但原方案不能直接交给旧训练器。**独立标签覆盖层身份／索引／掩码测试通过；训练环节仍阻塞，输出中明确`training_ready=false`。

| 审核发现 | 处理方式 |
|---|---|
| 仅屏蔽监督损失不能保证样本不影响训练 | 当前网络使用BatchNorm。不确定窗口若先进入训练前向，仍可能影响批统计／运行统计；合成张量已复现。若意图排除其训练影响，须在训练前向前按索引过滤，而不是只把损失乘0。 |
| 旧损失／指标入口不支持-1 | FocalLoss直接gather目标索引，-1报错；现有指标和采样也只接受二分类。旧入口还校验历史标签／哈希。不能将新标签旁文件直接塞给冻结训练入口，也不能为适配旁文件取消旧入口校验。 |
| 改标签后旧来源元数据和采样不再一致 | 重新生成`normal_origin_reference`，分别为原无故障、故障案例中的未激活段、故障末端、不确定末端；不沿用旧phase／fault_fraction／fault_onset_row。未来采样概率和类别权重需按实际可用标签重算。 |
| 训练文件不只有165120个源窗口 | train.pt总168800窗口，末尾3680是历史RflySim正常补充。独立覆盖层保留全部索引、原标签和suffix，不虚构其逐案例来源，不把未重新审核写成质量通过。 |
| 标签资格与输入质量混淆 | 151个来源分歧和192个时钟异常窗口分别保存。不确定标签及已知时钟异常作为前向候选的保守排除条件；但候选剩余仍有输入缺口，不能由候选布尔值推出输入已批准。 |
| 旧／新对照可能被不同样本范围混淆 | 若做标签修订受控比较，旧标签臂／新标签臂使用相同候选索引和同一统计，明确监督样本数变化；旧全量成绩另列，不能拿不同覆盖范围直接比较后宣称标签修复提升。 |

本轮对BatchNorm的检查只用合成张量，没有加载UAV网络权重、运行数据集模型推理或执行优化器更新。

## 2. 独立版本包含什么

目录`artifacts/fixed_crop_label_review_v1_20261031/`：

- `train_overlay.npz`／`val_overlay.npz`：与旧缓存一一对应的原索引、历史标签、新参考标签、标签定义掩码、已知时钟标记、前向候选索引掩码；**没有复制或修改X**。
- `train_metadata.csv`／`val_metadata.csv`：更新后的来源分组，保留原案例和工况、缺口诊断。未知字段保持未知，特别是RflySim补充块不伪造case_uid、窗口行号或新质量结论。

## 3. 归一化与公平比较

本轮不拟合新统计，也不修改任何旧协议。若后续仅作受控源标签开发比较，双方可固定同一份历史train拟合统计以隔离标签变化；**这不意味着被暂缓的train窗口从历史归一化统计中被抹除**。不得声称所有被屏蔽样本对整个历史处理过程零影响。

前向前过滤是为了避免后续训练时这些行进入BatchNorm／损失；不确定来源仅决定标签监督范围，不改变实际时间序列。若另定“所有质量暂缓样本都不得用于统计拟合”的要求，应在新版本重新拟合训练统计并用于两臂共同输入，不能悄悄只给新模型换统计。

现有cap64确为按时间索引均匀抽取，不依赖标签，保留即可。但训练采样器可能使用类别／来源权重，这部分必须按覆盖层重算；不能为了保持历史概率强行把新故障参考放回正常来源组。评估也需同时报告总量、标签不确定量、质量暂缓量和明确标签上的指标。

## 4. 验证

新增` scripts/research/prepare_fixed_crop_label_overlay.py `，只生成独立覆盖层，不导入训练任务执行器。`tests/test_fixed_crop_label_overlay.py`验证乱序键对齐、索引完整性、重复／错误成员拒绝、标签和来源重建、异常掩码、补充正常块保留、输入不改，以及旧FocalLoss不接受-1和损失后屏蔽不能撤销BatchNorm状态影响。

本轮运行overlay、fixed-crop、clock、event-boundary、raw-suitability共54项测试通过。独立重新打开两个覆盖层及CSV，逐元素核对旧y、全部索引、来源标签／掩码与质量标记；10个输入文件身份回查一致，包括源缓存、归一化、清单、链接和协议。

这些检查认证的是准备产物与规则一致，**不认证GTD为独立物理损伤真值，也不证明模型会更好**。

## 5. 是否继续

- 已继续到：独立、可追溯的标签覆盖层与更新元数据准备，保留旧资产并验证通过。
