# 官方处理规则复核：标签时序问题不等于替代裁剪已正确

日期：2026-10-31。[返回项目进程](../../../项目进程.md)。本记录纠正[全量事件审计](source_event_boundaries_audit.md)与[候选试加工](source_reprocessing_probe.md)中把裁剪疑点写成已确认修复方向的过强表述。原始数字与历史产物保留。

## 当前结论

**不能确定候选裁剪比官方规则正确。暂停其正式采用与扩大试加工，不用找回故障后段或单元测试通过来证明真实边界。**有证据的标签时序不一致继续保留，但必须与裁剪选择、实时预处理和模型性能分别讨论。

| 判断 | 证据及限制 |
|---|---|
| 本地代码是否已改坏官方裁剪函数 | 本地官方工具仓库HEAD为3b5b326da73890efb3bae120e75e16a5ea03293c。与该提交上游源文件比较AST：find_fly_land_time、freq_adjustment、str_freq_adjustment和SHIL_data_reader均相同。不能把这些函数的观察结果归因于我们改过其实现；HIL话题选择JSON有本地修改，整体流程并非完全未改。 |
| 官方故障状态的语义 | 官网1.6说明ULog rfly_ctrl_lxl携带故障ID／参数；GTD的fault_state在发生故障时为1，否则为0。这支持核对时刻状态，而非把故障案例的所有片段都当故障。注入消息仍不是独立物理损伤测量。 |
| 官方论文能否证明当前窗口协议 | arXiv v2第4.1节验证悬停单电机故障，用12维速度／角速度／加速度／欧拉角、10ms时间精度并插值；不是本项目26／31通道、50Hz、150帧末端标签协议的正确性证明。也不能由论文使用插值就宣称该流程严格在线因果。 |
| 是否证明官方裁剪范围错误 | 没有。已有证据只是40条低油门变化处的截止先于原始注入、其他飞行状态标志仍未落地；没有完整物理飞行真值、任务结束意图或作者解释来认证必须延长。短时低油门、故障后仍有日志以及landed标志都不能单独决定应保留范围。 |
| 是否证明候选规则更正确 | 没有。2秒落地确认、0.2秒输入年龄是自设候选参数；135完成案例中126例未确认落地，不能把它当完整飞行边界认证。恢复窗口只是程序可行性，不是物理正确性或性能提升。 |

## 固定官方范围，单独核对标签

例：HIL/circling/motor/TestCase_10_2300000009。本地加工CSV保留35.423780至63.523780秒，50.723780秒起标故障；原始GTD首次激活88.349秒，ULog首次注入指令88.475456秒。原始时间覆盖该保留区间，区间内GTD没有激活。

本轮不改变该裁剪范围、不改连续输入，提取上游固定提交的重采样函数到内存执行：

| 目标网格 | 上游函数生成故障行 | 原始时间参考故障行 | 上游首次生成故障秒 |
|---|---:|---:|---:|
| 同区间20Hz | 257 | 0 | 50.723780 |
| 原区间50Hz | 641 | 0 | 50.723780 |

50Hz生成状态与现有本地CSV逐行一致。20Hz只是同区间重采样检查，**不是官方20Hz完整流水线复现，也不是对作者发布的某份处理文件做过验证**。旧产物字段名published_50hz_label_exactly_reproduced实际比较本地生成文件，不能按其英文名称误读为作者发布文件。

这一反例说明：即使不采用候选裁剪，本地按瞬时状态使用的标签也存在原始时间不一致。合理排查首先可保持官方边界，单独验证离散标签时间对齐；边界内没有注入时不能硬标故障。但把片段改为未激活参考，不等于批准其为绝对健康训练样本，更不说明模型误报都来自该问题。

## 复现环境与尚缺证据

官方README建议Python3.9.7、NumPy1.20.3、pandas1.3.4、pyulog0.9.0等；本地复核为Python3.12.4、NumPy2.5.1、pandas2.3.1、pyulog1.2.2。**尚未在完整官方锁定依赖环境、原始未适配配置下端到端复现**，不能说已证明所有官方版本都有同一问题。20Hz检查不能代替这个缺口。

本轮查阅官网、论文v2、工具README与固定提交源码；没有取得作者对这40条边界意图的确认。未提交Issue、联系作者、安装环境、改源码、重建缓存、训练或替换部署。

## 后续应按什么顺序

1. 保留官方处理作为基准，候选输出保持实验隔离；当前不把2秒／0.2秒规则推广为新训练集。
2. 尽可能用官方建议环境和固定代码／配置复现最小案例；必要时使用原始副本，避免官方转换器写入原始目录。确认版本、时钟原点和字段语义，不因仅换单位就自动认为对齐。
3. 裁剪保持不变，先比较原输出与时间戳标签参考；评估裁剪外才注入的案例应如何标注／隔离，另记版本，不悄改冻结成员。
4. 若要改变裁剪，须补任务指令、完整起降／安全状态和输入覆盖证据，必要时向作者确认。边界不能根据标签或模型成绩择优；新规则需有独立依据，而不只比官方多留故障窗口。
5. 先解决上述一致性后再决定正式加工；本次不批准新协议或模型训练。
