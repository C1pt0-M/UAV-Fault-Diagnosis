## 1. 已有记录：做过什么、为什么失败

| 做法 | 结果 | 结论 |
|---|---|---|
| 只用源域训练，直接用在 Real 上（10-30 v1，11-06 M0/ENS 事件级） | 主正常告警占用约 94%，分数饱和在 1 附近；调阈值、换 ENS 都没用 | 源域模型把 Real 整体当成故障 |
| BN 统计更新、逐通道仿射对齐（v1、BN estimator、D1） | 误报只从约 100% 降到约 95% | **已关闭** |
| 只加 Real 正常做适配（v2 D2/D3，GBT 加 adapt_normal） | 正常误报约 0，但故障窗口召回只有 3.7%/5.5% | 学到的是“Real 的样子就是正常” |
| 补充探查 | 130 维窗口统计区分源和 Real 正常，AUC = 1.0；Real 的窗内波动是源的 2–7 倍（acc_norm、gyro、ctrl_3） | 域差异远大于故障本身造成的变化 |
| 历史 few-shot（旧 31 维、旧标签、离线三分类） | 训练里用了带标签的 Real，Real holdout Macro-F1 0.79，但正常召回只有 58% | 协议不同，只说明“带标签的 Real 有信息”，不能直接引用 |

**还没有在 causal_input_v1 上试过的唯一路线：用少量带故障标签的 Real 数据做监督。** v2 测试报告的结论也指向这里，但它要求重新划分 Real，并与测试部分严格隔离。

## 3. 本阶段的研究问题

**Q-B：有少量带标签的 Real 数据时，能不能得到可用的 Real 检测器？需要多少 Real 标签？源域预训练能起多大作用？**

- H1（源域价值）：在同样多的 Real 标签下，“源 + Real”优于“只用 Real”，标签少时差距最大。
- H2（可用性）：用全部 Real 开发数据时，Real 上能找到一个工作点，正常误报远低于只用源域的结果（约 139 次/小时），同时新确认的故障检出保持在较高水平。
- 信息增益：
  - H1 不成立，说明源域仿真对 Real 没有帮助，跨域研究应转为“Real 本身的小样本问题”；
  - H2 不成立，说明 Real 现有标签或输入不支持检测，应回到数据层面查；
  - 两者都成立，就进入深度骨干（T1）阶段。

## 5. 分阶段计划

### B0：零训练诊断（CPU，只用开发池）

先看清 Real 内部有没有和源域类似的混杂，再决定怎么定义正常样本。

1. **Real 内部捷径检查**：用 130 维统计、按组 CV，区分“Real 独立正常飞行”和“Real 故障案例的故障前段”。AUC 高，说明 Real 内部也有批次或会话差异（类似 Q2 的高度混杂）。那样的话，正常误报必须同时在两类正常上报告，训练时也不能只用其中一类作正常。
2. **只用 Real 的可分性上限**：只用 Real 开发池训练 GBT，按组 CV，看故障窗口与正常窗口的 AUC。接近 0.5 说明 Real 标签或输入本身就分不开，B1 就没有意义。
3. **标签核查**：故障参考点的分布、每个案例故障前正常段的长度、quarantine 是否已经排除。

### B1：学习曲线（主实验；CPU、GBT，零 GPU）

- **折**：开发池按组分 3 或 5 折。每折里，Real 训练部分再按 10%、25%、50%、100% 的组子集抽取，每档多个随机子集。
- **臂**：
  - **S**：只用源域（冻结的 `gbt_full_train.pkl`），作参照；
  - **R**：只用 Real 训练部分的 GBT（同一配方）；
  - **S+R**：源 train + Real 训练部分重拟合 GBT，Real 窗口加权；权重网格事先登记，只在训练折内选。
- **工作点**：在训练折内选，规则仿照源域逐类原则：motor / sensor 的故障召回都不低于参照水平，正常误报最低。参照水平的具体定义冻结时写死。
- **指标**：
  - 窗口：AP，以及固定召回下的正常 FPR；
  - 事件（主）：Real 正常飞行每小时误报事件、故障前误报、新确认检出、确认时延；
  - motor / sensor 分层，并用组 bootstrap 给 CI。
- **判据**（冻结时写成数字）：
  - H1：25% 档上，S+R 对 R 的正常误报比值（或 AP 差）CI 不跨过 1（或 0）；
  - H2：100% 档上，事件级正常误报 ≤ S 的 10%，同时新确认检出 ≥ S 的 80%。具体数值冻结前再和你确认。

### B2（视 B1 结果再定）：T1 MSTCA 骨干

只有 B1 显示带标签的 Real 有用（H2 成立）时才启动：
- 先在服务器上按固定 100 轮配方，重训 T1 全量源模型（1–3 个 seed）；
- 然后用 Real 开发池微调，与 GBT 的 S+R 比较；
- 需要先把 Real 案例数据传到服务器。

## 6. 不做什么

- 不再做 BN、仿射或只加正常数据的适配（已关闭）；不在旧 Real 测试结果上做任何调整。
- 跨数据集泛化不是目标；不换数据集。
- B0/B1 不动 GPU，不重训 MSTCA；不读封存部分。
- 结项报告等跨域实验结束后再写。

## 7. 主要风险

- **Real 正常太少**：完整正常飞行只有 48 个，开发池约 34 个，正常曝光不到 1 小时。事件级误报的 CI 会很宽，所以要同时用故障前正常段来补。
- **Real 内部捷径**：如果故障批次和正常批次在高度、场地、日期上不同，Real 内训练出的检测器可能只是在识别批次。B0 第 1 项就是为了提前发现这一点。
- **不是盲测**：所有 Real 故障案例都被汇总评估过，封存部分的结论边界必须写清楚。
