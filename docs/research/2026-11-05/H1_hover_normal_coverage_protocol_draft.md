# H1 悬停后段正常覆盖实验：协议草案（待审）

日期：2026-11-05。状态：**已冻结**（`configs/experiments/h1_hover_normal_coverage_v1.json`）。§4 draws 取 (a)、§5.2 小幅容忍、判据 1 取 50%，均按草案推荐值执行，负责人未另提意见。

## 1. 假设

M0 在独立正常 hover 后段的高误报，主要来自训练数据中该状态几乎只有故障标签：train hover 窗末 >30 s 的监督窗为故障 14975、独立正常 1237（12.1:1）；>50 s 为故障 4466、正常 13。

若只增加该状态的正常训练覆盖，而误报显著下降且故障召回不降，则支持"数据覆盖是主要原因"；若误报不降或召回同步下降，则该假设不足以解释问题。

本实验检验的是数据覆盖，不是方法创新。

## 3. 唯一改动：train 独立正常 hover 案例全量取窗

- 范围：train 中 56 个 `*/hover/no_fault/*` 案例（SIL 28、HIL 28，28 个配对组）。其他所有案例、val、norm_stats 均不变。
- 规则：在 `cases/*.npz` 原时间轴上，以原 cap64 相同的步长 5 帧、150 帧窗取全部起点；保留窗内 `row_input_valid` 全为真、末端 `row_label_valid` 为真且 `reference_state==0` 的窗口。已核对：该 56 案例所有 cap64 起点都在步长 5 网格上，且 91 个 hover 正常案例 5688 个 cap64 窗由 `cases/` 重建与 `windows/` 逐元素相同（最大差 0）。
- 数量：这 56 案例的合格窗由 3513 增至 23086；窗末 >30 s 由 1237 增至 8311。训练集总量 162069 → 181642。
- 窗口变换与 `causal_input.canonical_window` 相同（物理空间重算 acc_norm、逐窗减首气压、原源 train 统计标准化）。**不重新拟合 norm_stats**，避免同时改变全部通道的标准化。
- 新增窗口沿用 `normal_origin=normal_flight`，与原窗合并后一起参与 Balanced 权重计算。

### 3.1 采样质量的变化（必须明确）

**更正（CPU 检查中发现）**：草案原先以为 Balanced 规则下独立正常的总质量不变。实际上 `sampling_weights` 给每个正常来源的质量等于“正常窗口总数的一半”，窗口一多，正常总质量就跟着增加。第一次 CPU 检查里，故障采样概率从 0.4876 掉到了 0.4350，这等于同时改了类别先验，与本假设无关。

修正做法：Balanced 权重算完后，把全部正常权重等比例缩放，使正常总质量等于 M0 的 83051。修正后的检查结果：

- 故障概率 0.48756（与 M0 相同）；两种正常来源各 0.25622（与 M0 相同）
- 目标层（独立正常 hover >30 s）质量：1.50% → **5.23%**（草案估计的 10% 有误）
- 独立正常内部其他窗口的质量相应下降

所以补窗的效果只是在独立正常池内部重新分配质量，正常总量和类别先验都不变。其他飞行目录的独立正常误报可能因此上升，必须作为约束检查（见 §5.2）。

不另设"上调总正常质量"的臂：那会同时改变正常/故障先验，与本假设无关。

## 4. 训练设置（与 M0 B 完全一致）

模型 OnlineMSTCA（26 通道，hidden 64，105938 参数）；从 M0 相同的未训练 seed42 initial 映射初始化；seed 42；WeightedRandomSampler 有放回、Balanced；AdamW lr 3e-4 / wd 1e-4，batch 512，FocalLoss γ=2，clip 1.0；max 100 epoch，warmup 5，cosine 至 1e-6；全源 Val Macro-F1 严格最大选 best；早停 min 30 / patience 20 / delta 0.002；argmax 判定。

唯一需要说明的差别：**每 epoch draws**。两种选择：

- (a) 保持 162069 draws（推荐）：每 epoch 梯度更新数与 M0 相同（317），总优化预算可比。
- (b) 改为 181642：等同于"数据多了就多走步"，会混入预算差异。

推荐 (a)。

## 5. 成功判据（训练前冻结，结果出来后不改）

全部在全源 Val 34710 上，固定 0.5，用 best checkpoint。

### 5.1 主要目标（全部满足）

1. 独立正常 hover >30 s FP 从 222/280 降到 **≤140/280（≤50%）**。
2. 12 个后段 hover 正常案例中，**至少 8 个**案例的 >30 s FPR 低于 M0 B 的对应值，且 6 个配对组里至少 4 组两个域都下降。（防止少数案例主导）

### 5.2 约束（全部满足）

3. 故障总 Recall ≥ 16428/16970 − 85 TP（即下降不超过 0.5 pp）。
4. 六类各自 Recall 下降不超过 1.0 pp；SIL、HIL 总体 Recall 各自下降不超过 0.5 pp。
5. **hover >30 s 故障窗**（3323 个，M0 B 为 3245/3323 = 97.65%）Recall 下降不超过 1.0 pp。这是"模型是否只是把 hover 后段一律判正常"的直接检查。
6. 独立正常其余五个飞行目录合计 FP 不超过 M0 B 的 138 + 30。
7. 全正常 FP ≤ 417。

**关于容忍度**：M3 用的是"零下降"硬约束。本实验改用小幅容忍，理由是单 seed 下 M0 自身存在 1 pp 量级的波动（M0 U/B 两臂故障 Recall 相差 1.07 pp），零下降会让一个有效的数据结论因噪声被否掉。这是一个需要负责人确认的选择；若坚持零下降，请在冻结前改。

## 6. 局限

- 新增窗与原窗来自同 56 个案例，窗口高度重叠，有效信息远少于窗口数增幅；结果不能视为增加了独立样本。
- val 后段 hover 正常只有 12 个案例、6 个配对组、280 窗；按案例和配对组报告，不做显著性判断。
- >50 s 正常覆盖几乎无法补（13 → 69），val 中 >50 s 正常也极少，故本实验不能回答 50 s 以后的问题。
- 单 seed；通过后才做多 seed。
- 不读 internal test 与 Real。

## 7. 后续采集需求（供 RflySim 准备）

- 剖面：起飞爬升 → 稳态悬停，总时长 60–80 s（对齐故障案例的日志长度，中位 46.6 s、上四分位 66.6 s、最长 80.3 s）；覆盖几种悬停高度。
- 必须记录逐话题 ULog（或含 publication/sample 时间戳的等价记录），以通过 `causal_input_v1` 同一套年龄门禁；没有逐话题时间的数据（如历史 3680 后缀）不能进入因果版本。
- 最好同时采少量 RflySim 故障会话，避免模型学到"RflySim 来源 = 正常"。
- 按会话划分训练与留出。
