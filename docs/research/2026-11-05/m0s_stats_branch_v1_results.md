# M0S：M0 加窗口统计分支，train 内 3 折交叉验证

日期：2026-11-05。配置：`configs/experiments/m0s_stats_branch_v1.json`（跑之前冻结）。脚本：`scripts/research/train_m0s_stats_branch.py`。产物：`artifacts/m0s_stats_branch_v1_20261105/`。服务器 autodl_UAV（RTX 4090 D，torch 2.5.1+cu124）。

## 设计

- 在 M0 上加一个分支：对输入窗口按通道算 5 个统计量（均值、log 标准差、最小、最大、log 差分均值）得到 130 维，用固定均值和标准差标准化，经过 Linear(130,64)-ReLU-Linear(64,128)，加到 M0 编码器的 128 维输出上。分支的最后一层零初始化，所以第 0 步的输出与 M0 完全相同，4 个 run 都已核对。新增 16704 个参数。
- 训练流程、初始化、采样、预算、选点规则都和 M0 B 一样。3 折用两折训练，预测 held-out 折，与 feature_groupcv_v1 里对应折的 M0 比较；另外跑了一次全 train 训练，在源 val 上与 M0 B 对比，作为次要参考。
- 判据 d 改成“悬停 >30 s 之外”的每类召回降幅 ≤1 pp；悬停后段的 GPS 和 Baro 单独报告。这个修改是在 feature_groupcv_v1 失败后、本实验开始前决定的。

## 判定

**未通过**：判据 a、c 通过；b 失败（第 1 折故障 TP 少了 250，超出允许的 129）；d 失败（Baro 在悬停后段之外下降 2.59 pp，主要来自 velocity 和 acce 两个工况）。

## 结论

1. 神经网络分支学到的东西比窗口统计树模型少：误报降幅约是 ENS 的一半，而且召回还掉了，ENS 的召回反而略升。
2. 在源 val 上，全 train 版本的总误报没有下降，只有悬停后段改善。
3. 可能的原因（未验证）：分支只是加到编码器输出上，和 M0 共用同一个分类头，M0 的捷径没有被替代；另外，树模型能做阈值式切分，单层 MLP 在同样的统计量上未必能学到。
4. 本轮只有一个 seed，各折之间波动也大（第 1 折误报降了 495，第 2 折只降了 40）。
