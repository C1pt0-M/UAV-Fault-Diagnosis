# 窗口统计特征：train 内按配对组 3 折交叉验证

日期：2026-11-05。协议：`configs/experiments/feature_groupcv_v1.json`（跑之前冻结）。产物：`artifacts/feature_groupcv_v1_20261105/`。

## 设置

- 按 association_group 哈希把 train 分成 3 折（54177/52756/55136 窗），同一对 SIL/HIL 在同一折。
- M0：冻结的 M0 B 训练流程，用两折训练，选点仍按完整源 val，然后预测 held-out 折。服务器 autodl_UAV（RTX 4090 D，torch 2.5.1+cu124），3 折的初始化 digest 都和 M0 一致。best epoch 48/40/49。
- GBT：130 维窗口统计，超参固定，不使用 val。
- ENS：M0 和 GBT 概率平均。阈值 0.5。

## 结果（3 个 held-out 折合计）

|指标|M0|GBT|ENS|
|---|---:|---:|---:|
|全正常 FP|3717|2292|2384|
|故障 TP /81018|77311|77205|77453|
|独立正常 hover >30 s FP /1237|1129|686|726|
|其中 SIL / HIL|597 / 532|475 / 211|495 / 231|
|独立正常非 hover FP|2057|1376|1425|

每折全正常 FP（M0 → ENS）：1121→666，1619→1122，977→596；每折故障 TP 都没下降。

六类故障召回下降（M0 → ENS，pp）：GPS 2.24，Baro 1.42，Gyro −2.85，Mag −1.30，Accel −0.57，Motor −0.15。

## 判定

按冻结判据，GBT 和 ENS 都**未通过**：判据 a、b、c 通过，判据 d（每类召回下降 ≤1 pp）失败，失败项是 GPS 和 Baro。

## 失败项分析

- GPS 的损失全部在悬停后段：悬停 >30 s 的 GPS 故障窗 942 个，M0 检出 915，ENS 检出 724；其他工况 M0 5388、ENS 5427。
- Baro 也类似：悬停后段 847→775，其他工况 5183→5167。
- M0 在悬停后段把 1129/1237（91%）的独立正常窗也判成故障。所以它在这一层对 GPS 的高召回，很大程度上来自"稳态悬停就判故障"，并不是真的区分出了 GPS 故障。可分性分析里，GPS 在这一层的单通道 AUC 只有 0.63，GBT 只有 0.80，也与这个解释一致。
- 这是一个解释，不改变本轮"未通过"的判定。

## 结论

1. 窗口统计带来的误报下降在 train 内 3 折上是稳定的：每一折都降，总召回不降。
2. 它没有通过"每类召回不降超过 1 pp"，代价集中在悬停后段的 GPS 和 Baro。
3. 现行判据以 M0 为基准，而 M0 在悬停后段的部分召回来自捷径。这部分召回，任何去掉捷径的方法都会损失。下一步如果要改判据，必须在新实验之前冻结，不能用来回头改本轮结论。
