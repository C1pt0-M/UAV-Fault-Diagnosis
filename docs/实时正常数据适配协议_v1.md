# 实时检测：目标域正常数据适配协议 v1

> 协议编号：`rflymad_online_normal_adapt_v1`
>
> 状态：**已冻结**
>
> 冻结日期：2026-10-29
>
> 当前主模型：远端 `kg_mstca_v2`，协议中的数据角色和评估规则对后续实时二分类模型同样适用。
>
> 机器可读成员清单：`artifacts/normal_adaptation_audit_20261029/real_case_roles_v1.csv`
>
> 机器可读协议：`artifacts/normal_adaptation_audit_20261029/normal_adaptation_protocol_v1.json`

## 1. 研究问题

在不使用 RflyMAD Real 故障样本进行训练或适配的条件下，利用少量目标域正常日志降低正常飞行误报，同时保持故障事件召回和检测延迟。

这是一项**目标域正常数据适配**实验，不是零样本迁移，也不是使用 Real 故障标签的监督微调。正常数据适配本身不是论文创新点；它只是固定实验条件，真正的方法创新必须另行提出并通过对照验证。

## 2. 数据边界

### 2.1 源域训练数据

源模型训练只使用现有 `online_cache_v2` 的训练集合：

- SIL/HIL 的 `train` 窗口；
- 已纳入训练缓存的 32 个 RflySim 正常会话；
- 标签为 `normal / fault`，其中 motor 和 sensor 合并为 fault；
- 不使用 RflyMAD Real 日志。

源域 `val.pt` 只用于早停、模型选择和训练参数确定；源域 `test.pt` 只用于内部最终报告。源域数据和 RflySim 正常留出数据不能用于选择 Real 测试阈值。

### 2.2 输入合同

所有实验固定使用当前 26 通道合同和现有缓存版本：

- 采样频率：50 Hz；
- 窗口：150 帧，即 3 秒；
- 窗口清单步长：5 帧；
- 每个案例最多 64 个窗口，采用按时间均匀抽样；
- 窗口标签：按窗口末端时刻的 `normal / fault` 状态确定；
- 输入归一化：始终使用源域训练集拟合的 `norm_stats.json`；
- 不使用 Real 适配集、校准集或测试集重新拟合输入均值和标准差。

原有 `rflymad_case_split_v2` 不修改。下面的 Real 角色是覆盖在原 `external_test` 上的新实验角色层，不把旧清单改写成新的基础划分。

### 2.3 Real 角色分配

465 个 Real 案例全部保留在本协议中，但只能按下表用途使用：

| 角色 | 数量 | 来源 | 允许用途 |
|---|---:|---|---|
| `adapt_normal` | 10 | 48 个 `retain_normal` 原无故障案例 | 仅用于目标域 BatchNorm 统计量重校准 |
| `calibrate_normal` | 5 | 48 个 `retain_normal` 原无故障案例 | 仅用于事先规定的告警阈值校准；不更新模型参数或 BatchNorm |
| `test_normal` | 33 | 剩余 `retain_normal` 原无故障案例 | 主 Real 正常误报测试 |
| `test_fault` | 392 | 223 motor + 169 sensor | 主 Real 故障事件召回、漏检和延迟测试 |
| `supplemental_normal_test` | 25 | `retain_normal_only` 保留正常片段 | 补充正常测试，单独报告，不参与适配和校准 |
| **合计** | **465** |  |  |

`retain_normal_only` 来自原故障案例的保留正常片段，不能当作与原无故障飞行等价的独立健康飞行；其中有短日志。因此它们只能作为补充正常测试，不进入适配和阈值校准。

正式成员以 `real_case_roles_v1.csv` 为准。成员清单由固定种子
`rflymad-real-normal-adapt-draft-v1-20261029` 生成：在每种工况内按
`SHA256(seed | flight_status | TestInfo_case_id_candidate_group)` 排序，每种工况选 2 个适配案例组、1 个校准案例组，其余原无故障案例进入测试。

`TestInfo.xlsx` 中重复的 `Real Flight case ID` 只是**候选关联标记**，不是设备 ID 或飞行 ID。相同编号的案例不跨适配、校准和测试角色拆分；这是一条保守的防关联规则，不声称它们是同一次飞行或同一台设备。

## 3. 模型实验臂

每个候选实时模型必须至少报告下面两个实验臂。两臂使用完全相同的源模型权重、输入合同和最终 Real 测试成员。

### A0：无目标域适配

- 加载源域验证集选出的最佳权重；
- 使用源域训练集的输入归一化统计量；
- 不读取 `adapt_normal` 的数据；
- 不修改模型权重和 BatchNorm 运行统计量。

### A1：正常数据 BatchNorm 重校准

A1 是本协议 v1 的固定正常数据适配方法，适用于包含 `BatchNorm1d` 的模型，例如当前 KG-MSTCA。

1. 加载与 A0 完全相同的源域最佳权重。
2. 冻结所有可学习参数，不执行反向传播和梯度更新。
3. 输入仍使用源域 `norm_stats.json`，不重新拟合目标域输入均值和标准差。
4. 清空模型内所有 `BatchNorm1d` 的运行均值、运行方差和批次计数。
5. 将 BatchNorm 层设为训练状态，其他层保持评估状态，确保 Dropout 不产生随机变化。
6. 按 `case_uid`、窗口结束位置的确定顺序读取 10 个 `adapt_normal` 案例；批大小固定为 64，`num_workers=0`，不打乱顺序，仅前向传播更新 BatchNorm 运行统计量。
7. 完成后将整个模型切换为评估状态，保存适配后的运行统计量；权重张量必须与 A0 完全一致。

没有 BatchNorm 的模型不强行套用 A1；它应报告 A0，或在新的协议版本中定义适配方法。A1 不使用任何 Real 故障窗口。

## 4. 阈值实验臂

为了区分“模型适配收益”和“只调阈值收益”，每个模型适配臂都要报告两种阈值设置。

### T0：固定阈值

按当前在线事件聚合默认值固定：

```text
window_size = 150
inference_every = 10 frames
onset_threshold = 0.60
clear_threshold = 0.40
k_on = 3
k_off = 3
min_event_s = 0.5
merge_gap_s = 0.5
```

### T1：仅用正常校准集校准 onset 阈值

对每个模型臂单独运行 5 个 `calibrate_normal` 案例，使用与最终评估完全相同的窗口、步长和前向处理。只用这些正常案例的所有推理点故障概率计算：

```text
q = quantile(fault_prob, 0.995, method="linear")
onset_threshold = clip(max(0.60, q), 0.60, 0.95)
clear_threshold = 0.40
```

`k_on`、`k_off`、最小事件时长、合并间隔和推理频率不因校准集结果改变。校准集不能用于选择模型结构、训练轮数、适配方法或最终测试阈值以外的任何参数。不得查看 `test_fault` 的结果后重新计算阈值。

每个报告必须同时给出 A0-T0、A0-T1、A1-T0、A1-T1，避免把降低阈值或提高阈值的效果误写成模型改进。

## 5. 评估规则

### 5.1 Real 主测试

主测试固定由 33 个 `test_normal` 和 392 个 `test_fault` 案例组成。模型、适配方法和阈值全部冻结后，才读取主测试结果。

主指标：

- 故障案例事件召回：命中故障案例数 / 392；另报 motor、sensor 分组召回；
- 故障案例漏检数；
- 正常案例事件误报率：出现至少一个事件的 `test_normal` 案例数 / 33；
- 正常曝光时长、误报事件数、误报事件数 / 小时；
- 事件检测延迟的中位数和分位数；
- 窗口级 Accuracy、Macro-F1、fault recall 仅作为辅助，不作为“实时检测完成”的主证据。

### 5.2 补充正常测试

25 个 `supplemental_normal_test` 案例单独报告正常事件误报率和误报时长，不与 33 个主正常案例合并为一个无条件结论，也不参与适配、校准和模型选择。

### 5.3 事件命中和延迟

- 预测事件与真实故障区间有时间重叠，记为事件命中；没有任何重叠，记为漏检。
- 事件在真实起点之前开始时，单独记录 `pre_onset_alarm`，不报告负延迟。
- 延迟只取真实起点之后开始的第一个有效预测事件的 `event_start - ground_truth_onset`；没有这样的事件则延迟记为缺失，同时保留事件命中结果。
- 不能用“首个预测事件时间 - 首个真实起点”直接产生负延迟。
- 真实故障起点来自当前数据标签合同，不宣称等同于物理损伤发生时刻。

### 5.4 RflySim 正常留出

现有 8 个 RflySim 正常会话、922 个窗口单独作为仿真正常留出。它们报告：

- 会话级误报数和误报率；
- 窗口级误报率；
- 按 hover、vertical、box、mixed 分组的结果。

RflySim 结果不能与 RflyMAD Real 结果合并，也不能称为真实飞行验证。RflySim 故障注入测试另行记录故障用例、注入时间和检测延迟。

### 5.5 严格实时边界

当前 RflyMAD 处理 CSV 的部分重采样流程存在依赖后一采样点的历史记录。因此，基于这些处理后 CSV 的评估统一称为**回顾性流式回放**，可以报告模型输出和事件指标，但不能直接宣称严格因果的物理检测延迟。

严格实时结论必须来自 RflySim 或其他按到达顺序、只使用当时已有数据的输入链路，并单独记录预处理等待时间、推理时间和事件聚合时间。

## 6. 选择与验收边界

- 源域验证集负责早停、模型结构和训练参数选择。
- Real 正常校准集只负责 T1 的 onset 阈值计算。
- `test_normal`、`test_fault` 和 `supplemental_normal_test` 不参与任何开发决策。
- 任何候选方法都必须与 A0 基线比较；不能只报告 A1 的绝对分数。
- 内部候选通过条件：在相同阈值臂下，主正常测试误报下降，同时主故障案例召回下降不超过 5 个百分点；延迟变化和不确定性一并报告。该条件是项目内部筛选门槛，不是论文领域通用标准。
- 若 A1 只降低误报但明显损失故障召回，不能发布；若只在补充正常片段上改善，不能称为主结论。

## 7. 不允许的做法

- 不从 465 个 Real 案例中临时挑选“表现好”的案例作为适配集。
- 不使用 Real 故障样本训练、更新 BatchNorm、早停、选模型或调阈值。
- 不用最终测试结果反复修改适配方法或事件规则。
- 不重新随机划分 SIL/HIL 基础集合。
- 不把 RflySim 正常数据、RflyMAD Real 数据和真实飞行混成同一个域名。
- 不把 KG-MSTCA 名称继续解释为知识图谱，也不把 A1 或 GNN 自动称为论文创新。

## 8. 复现证据

冻结协议和成员清单后，每次训练／评估至少保存：

- 本协议 JSON、成员 CSV 及其 SHA-256；
- 源缓存各文件 SHA-256、源归一化统计量 SHA-256；
- 源模型配置、权重 SHA-256、代码提交或源码 SHA-256；
- 适配臂、阈值臂和全部参数；
- 适配时实际读取的案例、窗口数和 BatchNorm 运行统计量；
- Real 主测试、补充正常测试和 RflySim 留出结果；
- 运行设备、推理频率、预处理耗时和输出目录。

本协议冻结的是数据边界、适配规则和评估规则；如果后续改变适配方法、样本成员、阈值规则或严格实时预处理，必须新增协议版本，不在 v1 上直接改写。
