# 悬停后段误报是否来自慢变量／阶段捷径

日期：2026-11-01。用户提出位置、高度、稳态姿态和控制积分偏置可能成为时间捷径。本轮只读当前源train/val元数据、上一轮固定36条hover案例的物理帧，以及已保存恢复预算模型的源val概率；没有模型推理／训练、ULog重审、GPU、最终test／Real、特征删除或归一化修改。

## 1. 结论：阶段混杂证据强，但“位置积累导致误报”表述不准确

- 当前26通道不含pos_x/y/z、时间字段或PID积分状态。不能把这些不存在的字段列为模型直接泄漏来源。
- baro_alt_relative按每个150帧窗减首值，不能直接携带从起飞开始积累的绝对海拔。原case canonical_rows中仍是绝对气压高度，但不能把那个中间文件误当模型实际输入。
- 其他通道大多只有全源训练统计的固定z-score，确实保留运行水平、姿态／方向和控制背景差异；归一化不等于去掉阶段／工况信息。
- 当前hover标签的时间关联确实很强：故障案例的合格正常末端全部在裁剪起点30秒以内，30秒之后全部为故障。但训练仍有独立正常hover后段，不能说后段正常完全没覆盖。
- 在这批固定正常案例里，明显前后变化集中于垂向运动、油门和PWM，姿态、磁力计、前三轴控制槽的平均水平变化较小。更符合“从爬升进入稳态的运行状态差异”，不是已证明的高度／积分偏置随时间累积。
- 保存模型的同批正常窗口分数随阶段改变，支持阶段捷径假设；没有做固定权重受控输入干预或同预算消融，所以仍不能锁定因果通道、宣称模型只看时间，或直接删通道。

## 2. 实际输入与预处理已核实

model_contract.py:47–74的26列：4控制槽、4输出槽、3陀螺仪、3加速度、逐窗相对气压高度、4四元数、3速度、3磁力计、加速度模。

causal_input.py::canonical_window先在物理空间重算acc_norm，气压高度减本窗首值，再转float32并做固定源train标准化。2258个本轮画像窗口全部核对了气压首位置的相同标准化值。合成测试也确认：高度常数偏置被消除，但窗内高度变化仍保留；固定全局z-score并不会消掉控制量水平差异。

因此：
- 相对气压高度不是绝对海拔，但会携带最近2.98秒内的爬升／下降模式。
- 四元数没有逐窗重新定义姿态参考，会保留绝对姿态／航向信息；双覆盖符号及坐标参考同样要谨慎，不能仅凭数值漂移就解释成物理能量。
- 控制槽输出可能受控制器内部积分影响，但当前未直接输入积分器状态；不能把所见控制变化未经核实叫做积分漂移。

## 3. 当前修订版标签与时间的关联（全部已准入hover窗口）

以窗口最后一个样本相对原裁剪起点的时间分组，不是启动时间、UTC、已认证飞行阶段或实际故障发生时长。

|源集合及来源|裁剪前30秒正常／故障|裁剪30秒后正常／故障|
|---|---:|---:|
|train故障案例|11084／7081|0／14975|
|val故障案例|2359／1456|0／3323|
|train独立正常案例|2276／0|1237／0|
|val独立正常案例|474／0|280／0|

其中40–60秒，故障案例train6083窗、val1388窗均为故障；独立正常train454窗、val108窗均正常。故障在前段也已有激活，因此不能写成“前段全正常、后段全故障”；准确的是**故障案例正常只出现在前段，后段缺同来源的正常对照**。

这意味着背景／运行阶段有可能作为分类捷径。但时间并非显式输入，独立正常后段也存在，且来源均衡训练已增加该正常来源权重；不能由这一张表证明模型必然依赖特定字段或归因全部误报。其他飞行模式和整个数据集也不能直接套用hover的时间分布。

## 4. 固定正常案例的26通道被动画像

沿用前一轮固定36案例，只从当前原已准入2258窗口计算26通道窗口均值和窗内标准差，不使用新增残差140帧资格再次筛选。对12个原正常案例，按原裁剪前／后四分之一在每案例内配对，再汇总；源val6案例对应3个SIL/HIL配对组，非6次独立试验。

所有26列均报告。以下为源val各案例前后“窗口均值的中位数”之差，以已冻结源train标准差为单位，再取跨案例中位数：

|通道|后段减前段，源train标准差单位|
|---|---:|
|vel_z|+2.814|
|actuator_ctrl_4（油门槽）|−0.545|
|actuator_out_1至4|约−0.425至−0.561|
|baro_alt_relative（窗内相对高度）|−0.436|
|att_q_x／y／z|约+0.0044／+0.0023／+0.0061|
|actuator_ctrl_1至3|各自绝对配对变化中位数约0.0003–0.0010|

标准差单位可描述跨通道变化尺度，但不等于模型敏感度／重要性；全局标准差受故障分布影响，幅度小不排除网络敏感，幅度大也不证明网络使用。

将这些窗口均值还原为物理单位作解释（不是再拟合统计）：

- 六个val正常案例前段垂向速度中位数约−1.92至−2.18 m/s，后段约0.001至0.006 m/s，即记录运动状态从向上运动转为接近零垂向速度。
- 前段油门槽约0.302–0.312，后段约0.265；第1输出槽约1302–1311，后段约1265。
- 窗内相对气压高度的均值前段约2.81–3.18 m，后段约−0.009至0.015 m。这是3秒窗中的运动形态，不是后段绝对海拔更低。

这些直接反对“这一批主要是绝对位置／姿态随时长积累”的描述，更支持首先研究爬升／稳态运行背景差异。但只是固定少量案例的被动画像，不能推广为所有正常日志或动态飞行工况。

这张被动对照不分离原始编码器、关系分支与门控责任。对旧关系分支而言，原vertical_consistency在绝对标准化速度上计算、控制输出相关代理保留背景，提供了可疑路径，但未通过干预证明实际因果贡献。

## 6. 当前处理建议

将工作假设修订为：**模型可能将“爬升／稳态及其控制响应背景”与故障混淆，而不是已证实读取了位置／时间泄漏。**不要为这个解释重新改标签、删正常后段或重裁原始日志。

也不直接删vel_z／油门／PWM或对全部通道逐窗去均值：这些信号可能同时承载真实故障补偿及稳态故障信息，错误处理会降低故障召回；前轮物理一致性残差稳态故障响应不充分已说明仅剩变化量／一致性并非充分方案。

若后续定位通道责任，可在源开发数据上预先固定小规模、物理合理的干预／消融，保留同覆盖、同时报告故障侧，明确分布外干预的局限。此为后续选项，本轮未实施，不需要现在开GPU或再审整库。
